# 叙事式技术写作风格

把技术内容写得像一个懂行的朋友在讲给你听，而不是一份规格说明书。

## 核心原则

1. **从体感和现象切入，不从定义切入。** 开头先描述一个读者有共鸣的场景或痛点（"今天的 Agent 干了一万次活，和第一次干活时几乎一样笨"），让读者先认同"这确实是个问题"，再引出主题。

2. **设问引导，自问自答。** 在逻辑转折处抛出问题，让读者带着问题往下读，再给出解答。常用句式：
   - "问题来了：……"
   - "这里藏着一个不太起眼、却很要命的缺陷。"
   - "所以这篇论文要问的问题是：……"
   - "听起来挺好，对吧？但……"

3. **少术语，术语必须"翻译"成人话。** 专业术语首次出现时附英文原文（如"技能（skill）"），并立刻用比喻或大白话解释（技能 ≈ "一份告诉 Agent 遇到这类任务该怎么做的操作手册"）。优先用生活化比喻：账本、复盘文档、操作手册、编译过程。

4. **先讲问题，再讲解决过程，最后讲效果。** 经典三段式：
   - 问题是什么：讲清楚现状的做法和它真正的缺陷（缺陷要具体，不要泛泛说"不够好"）
   - 怎么解决的：讲设计思路和关键决策（"为什么这么设计"比"设计了什么"更重要）
   - 效果怎么样：先讲评测方法怎么保证公平，再给数字

5. **数字要硬，出处要明。** 具体数字（涨了几个点、从多少到多少）是说服力的来源，必须准确、与原文一致。正反例都要给——掉分的案例、失败的迁移案例如实呈现，反而更可信。

6. **口语化但信息密度高。** 短段落，一段讲一件事。允许"说白了""打个比方""值得停一下想一想"这类口语衔接，但不堆废话、不喊口号。

7. **结尾收束升华。** 用"写在最后"式的段落，把技术内容拉回到对读者的实际启发（"对做 Agent 的人来说，这意味着……"）。

## 章节标题风格

用问句或短判断句，不用教科书式标题：

- 好：`## 一、问题是什么？`、`## 二、怎么解决的？`
- 不好：`## 1. 研究背景与相关工作`

## 禁忌

- 不要开头就堆术语和定义
- 不要罗列式写作（"本文贡献如下：1. …2. …"放在摘要里可以，正文要讲故事）
- 不要只报喜不报忧，负面结果同样有价值
- 不要为了通俗而牺牲准确性——比喻是辅助，数字和事实不能变形
