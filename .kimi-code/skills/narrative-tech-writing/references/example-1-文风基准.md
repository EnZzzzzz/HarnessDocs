# Agent 自进化（Self-Evolution）视频字幕整理


## 一、Agent 自进化是什么？

今天我讲一个我觉得接下来 agent 领域非常重要的概念，叫做 agent 的自进化，英文名叫做 self evolution。我相信 agent 这概念大家已经很熟悉了，大家现在在做 agent，基本上都已经知道几个关键词：一个叫 planning，然后第二个是 memory to use，加上 reflection，反思。

但这里其实有个很大的问题，不知道大家有没有发现，就是今天绝大多数的 agent，是干了一万次活以后，和第一次干活的时候能力几乎没有区别。你看，你今天让他做一份行业报告，他去搜索、去调工具、去写报告；明天你再让他做一份行业研究，他又从头再来一遍。昨天踩过的坑，今天继续踩；昨天走过的弯路，今天继续走。

所以我认为 agent 的下个阶段的一个非常非常重要的能力，就是我上面写的 agent 的自进化。先给大家讲一下什么叫做 agent 的自进化。我们先看传统的 agent，我们拿到任务以后，agent 先去做规划，对吧，去做 planning。然后做 planning，可能会去调到工具和使用工具，然后再去做行动 action，之后再给到我们 agent 一个结果。这个是传统的 agent 的一个方式：一个任务进来，他做规划、调工具、执行，之后到结果之内，这个任务就结束了。

但 agent 自进化的是不一样。我们在后面继续化，你看，我们拿到结果以后，他会干嘛？他会给到 feedback，然后他再会做一个反思 reflection。好，反思完，然后再获取经验；然后拿到经验以后，他会去做一个 update，更新，更新的就是我们的 agent。

所以你看，在自进化 agent，他完全避换就是：我们拿到任务，到规划，到执行，再到反馈，再到反思，再到拿到经验，再更新，最后再去给到 agent，再去做下一次执行。这个就是 self-evolution。这里最关键的其实是最后的 update，就是更新。因为如果只有反思的话，其实还不能叫自进化。OK。


## 二、Reflection 和 Self-Evolution 的区别是什么？

既然我们说 reflection 不叫自进化，reflection 和 self-evolution 自进化到底有什么区别呢？这个区别非常重要。

reflection 就是他会反思，我刚才是哪里做错了。比如说，我们的 agent 调错了一个 API，然后发现参数传错了，他想了一下应该用另一个参数，然后修改，那调用成功了。这个叫做反思：发现错了，反思，再去改一下这个参数。

但问题来了，如果下一次遇到同样的问题，他又发了一遍，重新的去反思一遍，其实他根本没有进化。所以自进化是什么？就是我拿到这个错误，他就去理解为什么错；理解完为什么错了以后，他就知道怎么去改。然后再做最关键的一步，就是改完以后永久的保存。这个就是整体的自进化里的过程。

所以 reflection 解决的是这一次任务，自进化解决的是下一次任务，这两个东西根本就不是一个层级。


## 三、什么是进化？

讲完自进化的概念，以及跟 reflection 反思的区别以后，我们再讲一讲 agent 到底是在进化什么。很多人一听到自进化，第一反应就是：是不是让 AI 自己去训练自己？其实不是这样。模型参数的更新，只是 agent 的自进化里面最重的一种。今天更现实的 agent 的自进化，我觉得是至少可以分成五层的。

第一层就是 memory，记忆。主要就是去记住我们的经验。比如说，agent 去做数据分析的时候，发现 A 数据员硬上拿不到数据，B 数据员稳定很多，它下一次优先调的就是 B。这就是最基础的，叫做 experiment accumulation，经验的积累。

第二层就是策略 policy，或者说也可以叫 prompt。在这里，agent 不只是需要记住这个事情，还要干嘛呢？还要去知道怎么去修改自己的方法。比如说，第一次完成任务我需要用 10 步，后面副盘也有发现，第三步、第五步、第七步完全没有必要，于是它就可以把原来的 10 步给它缩减到 7 步。这个时候进化的就是叫做 Planning strategy，就是规划的策略。

然后在第三层叫做 view。这一层我觉得大家就非常容易理解了，但是我也觉得会非常重要，也就是把它经验 experiments 给它固化成一个 skill。

我举个例子，第一次你让 Action 去分析一家公司的财报，它可能需要去找财报、去解析 pdf、去提取数据和计算指标、去分析业务、去生成报告，整个过程可能要折腾半个小时。但如果这个成功以后，Action 会把这一整套的成功入境封装成一个叫做 Financial Analyze Skill，也就是金融分析的技能。那下次遇到类似的任务会怎么办呢？不用重新的再去探索了，直接去调用金融分析的技能。

所以 skill 本身是什么？我就可以把它理解成被固化下来的成功的经验。这个时候 Action 才真正开始有了经验值了。

好，来到了第四层，就是 to 工具。比如说，Action 的发现现有的工具不够用了，那怎么办呢？它可能自己会写一段拍摄，去测试、去 debug，发现能稳定解决成一个问题。然后会干嘛？会把它注射成一个新的 tool。所以这个时候你会看到，Action 好像不是在它已有的工具箱里面去挑工具了，而是干嘛呢？而是自己去写工具，并且把它给放到工具箱里面。

第五层，模型成 model。这层就是大家比较快的能想到，就是模型本身的参数的更新。更新的可能就是通过我的思维的路径，我可能叫做 trajectory，轨迹。老板的轨迹可能沉淀到可能有个 dataset，数据级。然后拿数据干嘛？就大家熟知的去做 sft，对吧？或者去做 rl。做完训练以后，它就会得到一个新的模型。

所以总的来说，就是 Action 在真实环境里面跑了几十万条轨迹，把成功和失败的数据给它收集起来，自动的构造训练数据，再通过 sftrl 这样的一个模式去更新模型的参数。这个时候底层的模型本身都发生变化。这个我觉得也是最重的一层 self evolution，资金化。


## 四、自进化的地位和总结

讲完资金化的整个的五层的架构以后，我再讲一讲为什么 agent 的资金化会这么的重要。我举个简单的例子，你就能 get 到了。

假设我今天要去做一个我自己详书内容的 agent，第一周他帮我去写内容，然后发现技术科普类的平均点赞是 500，AI 职场类的平均点赞是 1500，它会不会调整选题呢？接下它又会发现，但具体数字的标题点击率会高 30%，它会不会把这个规律给写进自己的 skill 呢？

再过一个月，这个 agent 就已经知道我的内容方向是什么、我的观众喜欢什么、什么标题点击率高、什么选题容易爆、什么内容结构玩波率高。这个时候，它就会和我第一天拿到了这个 agent，它已经完全全不一样了。

所以它相当于是什么？相当于是 agent 的替时间课的进化，到了 agent 替加一时间课。所以这样的进化，才是我理解到的 agent 的资金化。

所以真正的 agent 就应该形成它的经验飞轮，也就是我通过执行，然后拿到 feedback，拿到反思 reflection，然后拿到经验 experiments，最后得到更新。更新完以后，得到一个更好的 battle reaction，这样不断循环。这其实就是一个叫做 experiments flywheel，就是经验飞轮。

所以我觉得，未来判断一个 agent 到底是聪还是不聪明呢，可能不再只去看它一次任务完成有多好了，应该再去看另一个一个指标，就是它做完 1000 次任务以后，有没有比第一次更强。

如果一个 agent 今天犯这个错误，明天还犯这个错误，那跑了 1 万次任务，依然像第一次在上班呢，那它其实就是一个可以循环执行的自动化程序。但如果每一次执行，都能够去沉淀成 memory policy，甚至变成更新的 tour 和新的 model，那这个 agent 才是真正开始拥有一种非常关键的能力，也就是 agent 资金化的能力。

所以未来真正厉害的 agent，不一定是出场的时候最聪明的 agent，而可能是在真实的世界里面工作的越久，就越聪明的 agent。
