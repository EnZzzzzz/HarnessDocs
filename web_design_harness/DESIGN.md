# Design Harness 设计规范

状态：v0.2，RSI Harness 三章汇报基线。范围仅为独立项目 `web_design_harness/`。

## 设计方向

以「设计研究刊物」组织阅读，以「设计师工作台」展示过程。暖白纸面、墨色大字、朱红批注构成主要识别；蓝色表示选中与修订。先提出一个具体问题，再展示推敲过程，最后留下可讨论的判断。

首页像一期研究刊物，工作台像翻到刊物里的案例折页。共享品牌、字体、间距和导航，内容布局根据叙事变化。避免渐变大字、玻璃卡片、无目的装饰图、整页仪表盘及泛化的营销文案。

## AppShell

`app/layout.tsx` → `AppShell` → `SiteNav` + `ChapterNav` + `main` + 页脚。

- 顶栏：76px 高、暖白不透明底、底部细线；左侧 DH 方印与站名，右侧本期标识；窄屏时展示三个章节入口。
- 桌面框架：左栏 208px，内容区自适应；全站最大宽度 1600px，居中。左栏展示刊期、三个章节入口和本期研究问题。
- 左栏在 1024px 及以上吸顶；内容页保持自然滚动。主内容内边距桌面 48px，平板 28px，手机 20px。
- 小于 1024px 隐藏左栏，顶栏保留三个章节入口；1024px 及以上隐藏顶栏章节入口（与左栏重复），仅保留品牌与刊期；小于 640px 隐藏品牌英文副标题和刊期，导航仍可直接使用，不增加抽屉操作。
- `/charts` 为图表实践；`/problems` 为 RSI 常见问题；`/framework` 为整体框架；`/skills` 为 Skill 版本管理；`/cases` 为评测用例集；`/review` 为评测与人的判断。`/` 跳转第一章，旧 `/workbench` 保留兼容跳转。导航通过 `aria-current="page"` 明确当前位置。
- 手机顶栏为品牌与章节导航两行，三个入口直接可用。
- 提供跳转到正文的键盘链接；每页一个 h1；所有操作使用语义化链接或按钮。
- 页脚为研究状态与上下页入口。AppShell 不承载案例切换状态。

## 色彩与变量

| 角色 | 值 | 用法 |
| --- | --- | --- |
| background | #f7f5ef | 全局暖白纸面 |
| foreground | #242521 | 标题与正文 |
| muted foreground | #72736b | 辅助信息，避免用于小字号正文 |
| border | #deded4 | 分栏、分隔线、稿件边框 |
| primary | #b83d2b | 主要入口、章节编号、编辑批注 |
| primary foreground | #ffffff | 主要按钮文字 |
| accent blue | #365bbb | 版本选中、设计标记 |
| canvas | #eceee8 | 工作台底色，叠加细点阵 |
| sticky | #f3e8af | 少量评审批注 |

shadcn/ui 使用 CSS 变量映射主题。业务组件使用全局语义类和设计变量，避免每页建立独立配色。圆角以 4–8px 为主；阴影只用于工作台内的纸张层次。

## 字体与节奏

- UI 和正文使用系统无衬线：Arial、PingFang SC、Microsoft YaHei；无需联网加载字体。
- 中文展示标题使用 Songti SC、STSong、SimSun、serif；英文展示标题用 Georgia，保留编辑刊物的厚重气质。
- 首页 h1：桌面 clamp 48–76px，手机 44px；文章页 h1：clamp 36–56px。
- 正文 15–16px，行高 1.8；说明 12–13px，行高至少 1.6；英文眉题 10–11px、适度字距。
- 间距按 4px 系列，主要使用 8 / 12 / 16 / 24 / 32 / 48 / 64。章节靠留白和细线分隔，不把所有文字装进卡片。

## 三章的内容职责

完整文案规划见 `CONTENT.md`。使用 `.kimi-code/skills/narrative-tech-writing` 技能，按具体问题 → 保存与比较的方法 → 下一步尚待回答的问题推进。

### 01 Skill 版本管理

从“改了几次后找不到原因”开始，讲快照、派生、差异和能力组合。版本管理配图为主，Prompt 和 Harness 配图可切换。结尾引向固定任务。

### 02 评测用例集

从“不同任务无法直接比较”开始，讲完整任务单、集合、版本固定，再引出可逐步完善的 Benchmark。当前用例集即可支持人工比较，不以自动评分为前提。

### 03 评测与人的判断

从“好看与好用可能不一致”开始，讲执行、人工查看、保留证据和形成下一次修改。自动评测按需补充，人决定保留与迭代。配图中的分数和状态一律为示例。

### 配图

用户提供的配图存入 `public/rsi/`。正文展示完整画面，不裁切成装饰封面；使用 Next Image 提供响应式加载，首图优先、其他懒加载。图片链接到原图，新标签页放大查看。图注说明页面意义与示例边界。按章节叙事插图，不集中堆成图册。

## 组件与交互

- 基础按钮使用 shadcn/ui Base UI Button，源码位于 `components/ui/button.tsx`，通过 `components.json` 管理后续扩展。
- 路由跳转使用 Next Link；普通按钮用 Button，不能把链接嵌进按钮。
- `ChapterHeader`、`StorySection`、`EditorialNote`、`ChapterFooter` 组织章节；`ProposalImage` 展示配图；`ChapterFigures` 承载小型配图切换；`AppShell` 负责布局。
- 所有可操作元素提供清晰的焦点环，触控目标至少 44px。配图切换按钮使用 `aria-pressed`，更新内容有可访问的状态提示。
- 动效仅用 160–220ms 的颜色、边框和透明度过渡。响应 `prefers-reduced-motion`，不使用持续漂浮、视差或滚动劫持。
- 首版内容为静态数据，无登录、后端、持久化或虚构的保存操作。

## 技术边界与验收

Next.js App Router + React + TypeScript + Tailwind CSS v4 + shadcn/ui。独立 package.json、pnpm 锁文件和端口 9358，不从兄弟项目导入运行时文件。

页面默认服务端组件；导航与配图切换是小型客户端交互边界。无重型动画与图表依赖。无远程字体或远程图片依赖。

验收：三个章节路由可直接打开与互相跳转，旧入口正确跳转；生产构建及类型检查通过；320px 起布局单列且无固定宽画布溢出；导航、原图链接与配图切换可用键盘操作；内容不伪装为真实研究结果。
