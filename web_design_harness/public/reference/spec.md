## 已确定的云端与本地边界

- 云端管理核心资产、用例、Benchmark、实验定义、执行记录、评分与对比。
- 本地 Runner 执行 Agent 和自动评测，管理 Workspace、项目进程及产物采集。
- 默认每个 Run 结束后自动同步实验记录与指定证据；完整源码和日志按策略归档。
- 上传由 Runner 的持久化后台队列处理，无需 Skill 或子 Agent；断网和重启后补传。
- 执行结论、评分和同步状态分别展示；仅本地的产物不承诺云端恢复。

## 产品定位

RSI Harness 是一个管理、执行和评测 Agent 能力迭代的平台。平台以云端保存核心资产，以本地 Runner 提供执行环境，并以 DeepSeekHarness 作为唯一 Agent 执行底座，形成以下闭环：

> 创建或修改能力版本 → 选择用例或 Benchmark → 在独立 Workspace 执行 → 采集产物并评测 → 同步实验记录与指定证据 → 对比与迭代 → 创建下一版本。

核心资产包括 Skill、Prompt、Harness、用例、数据集、评测集及其版本。首版主要执行产物为 HTML 页面和 React 项目。云端必须保存实验记录，产物文件按策略上传，本地执行现场不要求整体同步。

首版支持用户驱动的迭代；自动分析失败、修改能力并持续验证的递归自改进属于后续扩展，不作为首版前提。

## 目标与范围

### 产品目标

1. 集中管理核心资产，通过账号密码登录访问云端数据。
2. 让每次任务在有独立 ID 的 Mock Workspace 中运行，并保留可追溯的执行现场。
3. 用版本树展示能力的迭代路径，关联每个版本的修改、产物与评测表现。
4. 支持选择能力版本和 Benchmark 批量评测，比较不同能力版本及执行配置的效果。
5. 基于 DeepSeekHarness 执行任务，围绕其能力构建调试、评测与迭代流程。
6. 让执行配置和评分依据可追溯，支持复跑；不承诺生成式 Agent 的输出完全一致。

### MVP 范围

- 账号密码登录，按账号隔离数据；首版以单人使用为主。
- Skill、Prompt、Harness 的版本快照、派生关系、内容对比及默认版本设置。
- 用例及数据集管理，支持文本需求、附件和初始项目快照。
- Benchmark 管理，支持用例选择、评分规则与版本固定。
- 一个本地 Runner 集成 DeepSeekHarness，实现完整执行闭环。
- 独立 Workspace、进程与端口管理、日志、取消、超时和失败记录。
- 前端项目本地预览，默认同步截图和评测证据，支持源码与完整日志的可选归档。
- 基础自动评分及人工评分，支持两个实验的结果对比。

### 暂不纳入 MVP

- 团队角色体系、组织管理、公开资产市场。
- 多父节点合并、完整 Git 托管服务及复杂分支协作。
- 多机器分布式调度和大规模并发优化。
- 云端执行 Agent、云端运行动态前端项目。
- 自动修改 Skill 并自动晋升最佳版本。

多 Agent 兼容不属于当前产品范围，也不作为后续架构的预设要求。

## 术语与核心对象

| 对象 | 定义 |
| --- | --- |
| Skill | 可复用能力包，包含指令、脚本、资源及依赖说明 |
| Prompt | 可独立管理的提示词模板及变量定义 |
| Harness | 基于 DeepSeekHarness 迭代的执行配置或执行包，描述工具、流程、上下文策略和限制 |
| AssetVersion | Skill、Prompt 或 Harness 的不可变版本快照 |
| Case | 一次任务的定义，包括需求、输入、初始状态和预期结果 |
| Dataset | 对用例及相关数据的组织，支持标签和来源信息 |
| Benchmark | 固定用例版本及评分规则的评测定义 |
| Experiment | 一次单用例调试或批量评测的配置与结果集合 |
| Run | 一个用例的一次执行尝试，具有唯一 ID |
| Workspace | 为 Run 创建的本地独立工作空间 |
| Artifact | Run 产生并登记的源码、构建文件、截图等文件或内容，登记不代表已上传 |
| Evaluation | 对 Run 产物的评分记录，包含规则版本与证据 |
| Runner | 连接云端并在本地执行任务的进程 |
| DeepSeekHarness | 唯一 Agent 执行底座，由本地 Runner 调用；底座版本与被迭代的 Harness 资产版本分别记录 |

Case 回答「做什么」，Benchmark 回答「用哪些任务、如何评分」。同一用例可被多个数据集和评测集引用。
