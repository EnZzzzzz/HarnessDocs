# 实验管理与版本对比

[返回规格总览](../spec.md)

## 主要用户流程

### 调试一个用例

1. 用户登录，创建或选择 Case，填写需求、上传附件、选择初始项目。
2. 选择 Skill、Prompt、Harness 的具体版本，以及 DeepSeekHarness 支持的模型和运行参数。
3. 选择在线 Runner，提交任务；系统保存配置快照并生成 Run ID。
4. Runner 创建 Workspace，准备输入及能力包，调用 DeepSeekHarness。
5. 用户查看状态和日志；项目可以启动时，通过本地入口预览。
6. 执行结束后，Runner 按约定采集产物并评测，保存固定快照，将实验记录和策略指定的文件加入后台上传队列。
7. 用户查看本地预览、可用产物及评分，添加备注，从当前版本派生下一版本；云端明确标注文件是否已上传。

### 运行 Benchmark

1. 用户选择固定版本的 Benchmark 和能力组合。
2. 设置 DeepSeekHarness 支持的模型、重复次数、超时及支持范围内的并发数。
3. 系统创建 Experiment，将每个用例的每次重复拆分为独立 Run。
4. Runner 执行任务，平台汇总各用例结果和完成进度。
5. 用户查看成功率、分项得分、耗时、可获取的用量及失败原因。

### 比较并迭代版本

1. 用户选择两个实验，查看能力配置差异。
2. 平台按用例版本匹配结果，展示得分变化及对应产物。
3. 用户查看改进、退步和执行不稳定的用例。
4. 用户为版本添加标签、修改默认版本，或创建新的派生版本。

## 实验与执行记录

提交实验时冻结以下配置：

- Skill、Prompt、Harness 的版本引用；未使用的能力类型明确留空。
- Case 或 Benchmark 版本及展开后的用例版本列表。
- DeepSeekHarness 底座版本、模型标识及可获取的生成参数。
- Runner、运行环境、初始项目内容摘要。
- 超时、重复次数、并发数和评测配置。

支持查看实验列表、运行详情、实时日志、失败阶段、产物和评分。重新执行创建新 Run 并关联原 Run；失败尝试不得被覆盖。自动重试默认关闭，避免重复消耗。

## 提交与同步配置

- 提交实验时冻结产物采集配置及同步策略；默认采用「记录与证据」。
- 数据集用于组织用例；进行批量评分时选择固定版本的 Benchmark，展开为独立 Run。
- 每个 Run 结束后独立触发同步，不等待整个 Experiment 完成；实验执行进度与同步进度分别汇总。
- 后续用户可以追加完整归档，此操作不修改原实验配置，另行记录归档请求及状态。
- MVP 以云端提交、本地 Runner 执行为标准入口。本地命令行提交及离线创建实验属于后续扩展，复用相同 ID、配置快照和补传机制。
- 任意脚本产生的已有目录不自动视为平台实验；「导入已有实验」不纳入 MVP。


## 对比与可追溯性

- 实验对比展示能力版本、DeepSeekHarness 底座版本、模型、Benchmark 和运行环境差异。
- 仅对匹配的用例版本和评分规则计算直接得分变化；不匹配项明确提示并单独展示。
- 用户可从总分进入分项、用例、Run、截图和原始日志。
- 每个版本节点可查看相关实验，但不得用不同 Benchmark 的成绩直接确定全局最佳版本。
- 保留环境与工具版本用于排查差异；外部模型或服务变化可能影响复跑结果。
