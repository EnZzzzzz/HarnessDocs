# Benchmark 与评测

[返回规格总览](../spec.md)

## Benchmark 与评分

- Benchmark 版本固定用例版本列表、评测器版本、评分维度、权重和失败处理规则。
- 用户可以从数据集中选择用例创建 Benchmark。
- 同一 Run 可以产生多个分项评分，每项保存原始结果、归一化分数和证据。
- 评测器类型支持自动检查、浏览器测试、模型评审和人工评分；MVP 优先实现可运行性检查及人工评分。
- 人工评分记录评分人、时间和备注；修改分数保留历史记录。
- 重评同一产物创建新的 Evaluation，不覆盖旧记录。

建议的前端评分维度：

| 维度 | 示例证据 |
| --- | --- |
| 可运行性 | 安装、构建、启动退出码及日志 |
| 功能完成度 | 浏览器交互断言及失败截图 |
| 视觉质量 | 指定视口截图、参考图和评审说明 |
| 工程质量 | 静态检查结果、结构及可维护性评审 |
| 执行成本 | 耗时、后端可提供的 Token 和费用信息 |

评分约定：

- 归一化分项分数范围为 0–100，总分按 Benchmark 固定权重计算。
- 无结果、评测器故障和不适用必须明确区分，不得静默视为满分或零分。
- 是否将任务失败记零分、是否允许部分评分，必须由 Benchmark 规则明确规定。
- MVP 默认必填评分缺失时总分显示为「未完成」，同时展示已完成分项。
- 用量或费用无法获得时显示「不可用」，不得记为零。
- 多次重复执行保留每次结果，并汇总均值、离散程度和成功率。

## 评测证据与产物关联

- Evaluation 关联本次实际受评的产物快照及内容摘要，避免本地项目后续修改导致证据混淆。
- Benchmark 版本声明评分所需的证据；默认同步策略上传这些指定证据。
- 仅保存评分不代表已经保存了可重评的全部材料；重评前检查所需产物是否仍可获得。
- 自动评测通常在本地 Runner 执行，评分记录上传云端；人工评分在云端记录。
- 证据上传失败不改变已产生的评分，但云端必须展示证据尚未同步。
