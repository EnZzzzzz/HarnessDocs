# 本地 Runner 与执行环境

[返回规格总览](../spec.md)

## Mock Workspace

每个 Run 创建独立目录，建议布局如下：

```text
workspaces/<run_id>/
  input/          # 对 Agent 可见的输入材料
  assets/         # 本次能力版本快照
  project/        # 初始项目和生成代码
  logs/           # 执行日志
  evaluation/     # 评测阶段生成的报告
  artifacts/      # 待归档产物
  manifest.json   # 非敏感配置及内容摘要
```

- 不同 Run 不共享可写项目目录；共享缓存只能作为显式受控的优化。
- Runner 为启动的项目分配端口，记录进程并在结束或取消后回收任务进程。
- 创建 Workspace 前检查本地执行前提，准备失败时记录具体错误。
- 支持保留失败现场、手动清理和归档成功后按策略清理。
- 首版默认保留工作目录，自动清理须显式配置；不得因上传失败删除唯一产物副本。
- 独立目录不构成安全沙箱。MVP 面向用户可信的任务和能力包，容器级隔离作为后续增强。

## DeepSeekHarness 集成

本地 Runner 直接集成 DeepSeekHarness，不设计多 Agent 适配层或后端切换功能。集成应满足以下要求：

- 获取并记录 DeepSeekHarness 底座版本和可用能力。
- 检查本地依赖、授权状态和配置兼容性。
- 接收任务、Workspace、能力配置和运行参数。
- 启动、取消任务并输出结构化状态及日志事件。
- 返回执行结论、错误信息和可获得的用量。

模型与运行参数以所使用的 DeepSeekHarness 版本实际支持范围为准。图片输入、浏览器工具、会话恢复、用量统计等能力需在集成时确认；不支持的配置应在提交或执行前明确报错。

Harness 资产用于保存基于底座的执行配置或执行包，DeepSeekHarness 底座版本用于标识运行时实现。两者均需记录，以区分能力修改与底座升级带来的影响。

凭据通过本地配置或安全凭据存储提供，云端运行配置仅保存凭据引用，不保存明文。DeepSeekHarness 的具体调用方式和本地授权方式在技术设计阶段确认。
