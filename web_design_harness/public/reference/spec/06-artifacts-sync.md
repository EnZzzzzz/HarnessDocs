# 产物采集、预览与云端同步

[返回规格总览](../spec.md)

## 实验记录与 Agent 产物

实验记录是平台确定的结构化信息；Agent 产物是执行过程中生成并按约定登记的文件或内容。二者分别保存，不要求上传整个 Workspace 才能形成有效实验记录。

每个 Run 必须同步以下记录：

- Experiment、Run、用例及能力版本引用、实际执行配置和环境信息。
- 执行状态、关键事件、起止时间、耗时、可获得的用量、失败阶段和错误摘要。
- 评测状态、分项评分、结论及证据引用。
- 产物清单，包含类型、大小、内容摘要、所属 Run、本地可用状态及上传状态。

用量不可获得时明确标记不可用。凭据不进入记录或归档。

## 本地预览

- HTML 项目通过本地静态服务预览；React 项目按记录的安装及启动命令预览。
- 云端页面展示所属 Runner、本地地址和可用状态；其他设备不保证可以访问。
- 云端支持查看已上传截图、报告和下载已上传源码；历史项目在线运行不属于 MVP。

## 采集与快照

- Runner 根据用例的采集约定和评测器输出收集产物；该工作由程序完成，不依赖 Skill 或子 Agent。
- 默认采集范围包含源码、锁文件、非敏感配置清单、执行日志及已生成的截图和评测报告；构建文件仅在生成且配置要求时收集。
- 默认排除依赖目录、缓存和凭据文件；额外文件通过明确规则纳入。
- 执行及自动评测结束后，Runner 生成固定的产物快照和清单，再入队上传；后台上传不得直接读取仍会变化的工作目录。
- 快照记录内容摘要；后续新增产物或重评报告单独登记，不覆盖已有受评快照。
- 失败、取消、超时也收集已有产物；采集失败或文件缺失时记录原因，不阻止已有实验记录同步。

## 同步策略

| 策略 | 云端保存的内容 | 适用场景 |
| --- | --- | --- |
| 仅记录 | 配置、状态、指标、评分和产物索引 | 高频本地调试 |
| 记录与证据，默认 | 实验记录、指定截图、评测报告和必要的失败日志 | 常规实验比较 |
| 完整归档 | 再加源码、完整执行日志等采集约定内的文件 | 重要版本和长期保存 |

完整归档指上传约定内的产物，不是整个 Workspace。文件大小限制、配额及超限处理在技术设计中明确，不得静默丢弃应上传的文件。

## 自动触发与后台队列

1. 每个 Run 的执行和自动评测结束后，Runner 将记录及策略指定的产物加入本地持久化上传队列；无需等待人工评分或整批任务结束。
2. 后台上传器处理队列，后续 Run 可以继续执行。状态和关键事件可在运行期间先行同步。
3. 本地队列保存待上传项、完成状态和重试信息；网络恢复或 Runner 重启后继续处理未完成项。
4. 云端按 Run ID 和产物标识幂等接收，重复重试不产生重复记录；内容摘要用于校验文件完整性。
5. 文件上传成功并经云端确认后才标记已上传。记录同步与文件上传分别追踪，部分文件失败不能阻止已完成记录展示。
6. 后续重评或新增证据沿用同一队列补传。

上传和归档是 Runner 的确定性职责，不启动额外 Agent。上传故障不改变已知执行结果，也不阻塞后续执行，除非本地资源不足以安全保存待传数据，此时明确暂停新任务并报告原因。

## 手动操作

- 「重试同步」：重新处理失败的上传项。
- 「完整归档」：将本地仍可获得的约定产物加入上传队列，保留原实验提交策略。
- 不重复执行 Agent，也不重复评测，仅处理归档和上传。
- 本地 Runner 不在线时请求保持待处理；所需文件已丢失时明确报告不可归档，不得标记成功。

## 日志展示

云端默认展示运行状态、关键事件及必要的失败日志。在线实时日志可通过 Runner 主动建立的连接转发；实时查看不代表完整日志已永久归档。完整日志默认在本地保留，按完整归档策略上传。

## 可用性与清理

- 文件分别展示「仅本地」「待上传」「上传中」「已上传」「上传失败」等状态；本地副本另行展示可用、已清理或未知，Runner 离线不等于文件丢失。
- 只上传记录或证据时，云端不承诺能够恢复源码或完整执行现场。
- 本地材料被清理后，没有上传的文件无法从云端恢复；重评同一产物依赖所需材料仍可获得。
- 默认保留 Workspace，自动清理必须显式配置；上传失败不得删除唯一副本。
- 依照当前策略上传成功不代表所有本地文件均已归档；清理界面必须说明哪些材料只有本地副本。
- 对选择完整归档且归档成功的 Run，清理本地后仍可查看云端记录并下载已归档文件。
