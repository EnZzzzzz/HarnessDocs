# 架构、数据模型与异常处理

[返回规格总览](../spec.md)

## 云端与本地架构边界

| 云端管理平台 | 本地 Runner |
| --- | --- |
| 身份认证、资产访问控制 | 与账号绑定、心跳和能力上报 |
| 资产及版本元数据、文件存储 | 下载与校验指定资产版本 |
| 实验创建、任务队列 | 领取任务、创建 Workspace |
| 运行状态、关键事件与可用日志展示 | 调用 DeepSeekHarness、管理项目进程 |
| 结果聚合、版本对比 | 运行评测器、收集产物 |
| 产物索引及已上传文件访问 | 采集快照、后台上传、重传和本地清理 |

Runner 主动连接云端，首版不要求本地开放公网端口。离线 Runner 不领取新任务；平台应展示在线状态和最后心跳时间。

任务领取需具备所有权或租约机制，避免同一 Run 被重复执行。网络中断时 Runner 保存日志和结果，重连后补传。失联期间云端显示连接异常，不直接推断任务失败；在原任务状态未确认前不自动重新派发同一 Run。

## 概念数据模型

所有用户数据对象带有所属账号标识，服务端校验其访问权限。

| 实体 | 主要字段与关系 |
| --- | --- |
| User | ID、登录标识、密码哈希、状态 |
| Asset | ID、类型、名称、标签、默认版本 ID、归档状态 |
| AssetVersion | Asset ID、父版本 ID、快照引用、内容摘要、修改说明 |
| Case / CaseVersion | 任务定义及不可变输入快照 |
| Dataset / DatasetVersion | 数据集元信息及固定用例版本列表 |
| Benchmark / BenchmarkVersion | 固定用例版本、评测配置和聚合规则 |
| Runner | 账号、设备标识、能力、状态、最后心跳 |
| Experiment | 配置快照、同步策略、类型、基线实验引用、执行及同步聚合状态 |
| Run | Experiment ID、CaseVersion ID、重复序号、原 Run 引用、状态及时间 |
| Workspace | Run ID、Runner ID、本地路径、环境信息、清理状态 |
| Artifact | Run ID、类型、快照引用、云端文件引用、摘要、大小、本地可用状态、上传状态 |
| Evaluation | Run ID、评测配置版本、分项分数、证据、状态及评分来源 |

本地路径只用于定位执行现场；跨设备读取通过云端文件引用完成。配置中不得保存明文凭据。

Runner 本地持久化上传队列，记录 Run/产物标识、快照位置、上传进度、错误及重试信息。追加完整归档请求单独记录请求范围、时间和处理状态。具体存储结构在技术设计中确定。

## 状态与异常处理

Run 的主要执行状态：

```text
queued → preparing → running → evaluating → completed
```

活动状态可进入 `failed`、`timed_out` 或 `cancelled`。`completed` 表示执行及所需评测流程正常结束，不表示产物通过全部检查。若需人工评分，Run 可停留在 `evaluating`，并显示「等待人工评分」，此时不占用 Agent 进程。

同步采用独立状态：`pending → uploading → synced`，上传失败为 `upload_failed`，可以重试。`synced` 仅表示当前策略要求的记录和文件已同步，不代表完整归档；页面同时展示策略、已完成数量和缺失项。完整归档请求另行跟踪，全部约定产物经云端确认后才标记 `archived`。连接状态独立显示，不混入任务执行结论。

等待人工评分时，已有执行记录和产物仍可同步；执行状态、评测状态、同步状态分别展示。

- 安装或启动失败：记录失败阶段、退出码、日志和已有产物。
- 评测器故障：标记评测失败，保留产物并允许重评。
- 取消或超时：终止本 Run 管理的进程，收集已有结果；离线时显示取消待送达。
- Runner 进程重启：检查本地任务状态并向云端协调，无法恢复时保留现场并说明原因。
- 重复上传：按 Run 和产物标识幂等处理，避免重复记录。
- 部分用例失败：实验继续汇总，明确成功、失败、取消和未完成数量。

## 非功能需求

- 访问控制：资产、任务、日志和下载入口均在服务端校验账号权限。
- 认证与凭据：密码采用适当的不可逆密码哈希；云端通信使用 TLS；执行凭据不写入归档。
- 可追溯性：版本引用、配置快照、关键事件和文件摘要可查询。
- 一致性：队列领取、状态更新及结果上传具备去重和幂等处理。
- 可恢复性：日志和产物上传中断后可重试，上传故障不改变已知执行结果。
- 可观测性：错误报告应给出阶段、原因及关联日志。
- 可扩展性：评测器通过独立接口扩展；执行能力围绕 DeepSeekHarness 演进。
- 数据保留：历史引用不可被普通编辑破坏；归档清理与永久删除采用明确策略。

具体性能指标、文件大小限制、存储配额及支持的本地操作系统，在技术设计阶段确定。
