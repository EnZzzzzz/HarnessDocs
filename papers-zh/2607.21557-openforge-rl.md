# 在任意环境中训练 Harness 原生的智能体（OpenForge RL: Train Harness-native Agents in Any Environment）

- 作者 / 机构：Xiao Yu（哥伦比亚大学）、Baolin Peng（Microsoft Research）、Ruize Xu（达特茅斯学院）、Hao Zou、Qianhui Wu、Hao Cheng、Wenlin Yao、Nikhil Singh、Zhou Yu（哥伦比亚大学）、Jianfeng Gao（Microsoft Research）
- 出处：arXiv:2607.21557 [cs.AI]，2026-07-23 提交（v1），2026-07-24 修订（v2）；作者注明投稿 ICLR 2027
- 原文链接：https://arxiv.org/abs/2607.21557

## 摘要（中文翻译）

现代 AI 智能体（agent）高度依赖复杂的「推理 harness」（inference harness）——例如 Claude Code、Codex、OpenClaw——这些 harness 负责管理多轮推理、工具调用与外部系统交互。然而，由于标准的 SFT（监督微调，supervised fine-tuning）/ RL（强化学习，reinforcement learning）技术栈无法原生表达有状态、多进程的 harness 推理过程，这些 harness 很难用开源基础设施进行端到端训练。

本文提出 **OpenForge RL**，一个用于端到端训练基于 harness 的智能体的开源框架。它由两个核心组件构成：

1. **轻量级代理（lightweight proxy）**：拦截 harness 的模型调用（model calls），将其记录为标准 RL 代码库（如 veRL）可用的训练数据，并重构轨迹（trajectory）；
2. **Kubernetes 编排器（orchestrator）**：将每次 rollout 放在云端提供商的隔离远程容器中运行，从而支持规模化。

这一设计将训练（training）与推理（inference）解耦，使研究者可以在「任意 harness × 任意环境」上训练，且不存在训练–部署失配（train–deploy mismatch）。

验证工作覆盖了两类智能体：基于工具 / claw（爪，指智能体的抓取/操作工具集）的智能体，以及多模态 GUI 浏览器与计算机操作（computer-use）智能体。仅用数百到数千个自动整理的训练任务，**OpenForgeClaw** 在 ClawEval 上达到 31.7（pass³）与 55.9（pass@3），在 QwenClawBench 上达到 33.7；**OpenForgeGUI** 在 OSWorld-Verified 上达到 37.7，在 Online-Mind2Web 上达到 63.0，在 WebVoyager 上达到 72.3。这些结果在几乎全部基准上超过了相近规模的开放基线模型，并且在 GUI 场景中匹敌甚至超越了体量大数倍的开源模型。对 harness 选择（ZeroClaw、OpenClaw、Codex）与 RL 的分析表明，某些 harness「比其他 harness 更难学习」；RL 改善了诸如自我验证（self-verification）、工具覆盖（tool coverage）、多步计划完成等可靠性特质，但错误恢复（error recovery）能力「仍然较弱」。

## 核心贡献

- **OpenForge RL 基础设施**：将「任意 harness × 任意环境」灵活地与标准 RL 代码库（如 veRL）配对，打通真实 harness 生态与远程云沙箱（sandbox），使任何 harness 都能用标准 RL 技术栈端到端训练。
- **广泛的实证研究**：覆盖工具 / claw 智能体与 GUI（浏览器与计算机操作）智能体，结果在几乎全部基准上超越相近规模的开源模型，并在 GUI 场景匹敌甚至超越大数倍的开源模型。
- **对 harness 选择与 RL 效果的分析**：更简单的 harness 更易学习；跨相似 harness 的训练可以泛化；RL 提升了「智能体可靠性」（自我验证、工具覆盖、任务完成），但错误恢复依然薄弱。
- **数据合成流水线**：构建五阶段自动化流程合成 SFT 与 RL 训练任务（模拟人类任务整理过程），解决了除编码之外领域训练任务稀少的问题。

## 方法（中文翻译）

### 系统概览

论文将智能体任务建模为马尔可夫决策过程（MDP，Markov Decision Process）：LLM 智能体 πθ 接收观测（observation）、产生动作（action）并转移状态，直至获得终止奖励（terminal reward）。一个 harness H(π) 将智能体包裹起来，为其提供工具与各类控制流（子智能体 subagent、技能 skill、规划模式 planning mode），因此模型实际看到的上下文不再是原始交互历史。harness 推理过程中的每一对提示–响应记为 (H(sₜ), aₜ)。

### 代理机制（Proxy Mechanism）

核心创新是一个轻量级代理，它包裹推理服务器（如 vLLM），拦截来自 rollout 容器的所有生成请求。当一次 rollout 结束后，代理收集终止奖励（通常为任务成功与否）以及提示–响应对，重构出训练样本：

> τ = (s₀^H, a₀, r₀), ..., (s_T^H, a_T, r_T)；其中 r_t = γ^(T−t)·r_T

通常取 γ = 1.0。对于基于组（group）的算法（如 GRPO），优势（advantage）通过比较同一组内不同轨迹的样本平均奖励来计算。

### Kubernetes 编排

编排器基于 Orchard 构建，在云提供商（如 Microsoft Azure）上创建、删除并分配 rollout 容器的资源，实现并发 rollout 的弹性伸缩，同时避免训练节点过载。

### 处理实际工程挑战

- **异步 rollout 与超时**：由于 rollout 在远端运行，单个无响应的 rollout 可能阻塞训练。论文为每个 rollout 任务设置了宽松的墙上时钟（wall-clock）超时，而非按轮次（turn）限制——部分 harness（如 Codex）并不暴露轮次上限，且该定义在不同 harness 间并不一致。超时任务会被终止并返回错误信号，使训练得以继续处理其余 rollout。
- **错误处理**：遵循 DAPO 的做法，丢弃那些以环境错误（网络故障、harness 崩溃、超时）收尾的轨迹中的样本，因为不完整的 rollout 可能注入有误导性的训练信号。

### 数据合成流水线

由于除编码之外领域可用的训练任务很少，作者构建了五阶段流水线来合成 SFT 与 RL 任务，模拟人类的任务整理方式：

1. **提出（Propose）**——代理基于来自网页 / X API 或参考资产的现实场景，起草候选指令；
2. **剪枝（Prune）**——移除低质量与重复的任务；
3. **构建（Build）**——创建可执行的环境与验证脚本（verifier script）；
4. **测试（Test）**——用另一个开源 LLM / VLM 尝试完成该任务；
5. **打磨（Refine）**——修复缺陷，直至任务通过全部检查。

对于 claw 场景，参考池来自 ClawHub 访问权限与 ZClawBench 任务；对于计算机操作，使用 X 搜索 API、22k 条 AgentNet 指令与 Synthetic-Computer-Use 数据；对于浏览器操作，任务来自 WebGym（过滤以避免与评测基准重叠、仅保留热门网站并做去重）。Claw 的 RL 任务合成平均耗时 16.1 分钟、花费 4.36 美元/任务；SFT 任务更便宜（5.2 分钟、0.86 美元），因为跳过了测试-打磨环节，改用 GPT-5.4 评判。

## 实验结果

### Claw 智能体（OpenForgeClaw，30B-A3B MoE，基于 Qwen3-30B-A3B-Thinking，在 ReACT、ZeroClaw、OpenClaw 与 Codex 四种 harness 上训练）

| 基准 | pass³ | pass@3 | pass@1 |
|---|---|---|---|
| ClawEval | 31.7 | 55.9 | — |
| QwenClawBench | — | — | 33.7 |
| MCPAtlas | — | — | 28.1 |

SFT 从 MiniMax-M2.5 教师模型蒸馏（每任务 N=3 次 rollout，保留成功样本）；RL 采用 GRPO，batch size 8、组大小 8，在 8×B200 GPU 上训练约 48 小时。Azure 上 rollout pod 限 2 CPU/2GB 内存。

### GUI 智能体（OpenForgeGUI，8B，基于 Qwen3-VL-8B-Thinking，在 Kimi-Agent 与 Molmo-Web harness 上训练）

| 基准 | 得分 |
|---|---|
| OSWorld-Verified | 37.7 |
| Online-Mind2Web | 63.0 |
| WebVoyager | 72.3 |

SFT 从 Kimi-K2.5 蒸馏；RL 用 GRPO 在 8×B200 GPU 上训练。计算机操作 rollout 使用 Xvfb 虚拟显示（而非完整的 QEMU 虚拟机），每 pod 4 CPU/4GB；浏览器操作使用远程 Browser-Use Cloud 会话，最多 48 个并发 rollout，每沙箱 pod 2 CPU/6GB。

### 不同 harness 学习难度差异的发现

**（1）某些 harness 更难学习。** 在 ClawEval 上用四种 harness（ReACT*、ZeroClaw、OpenClaw、Codex）评测发现：支持直接注册自定义工具（ReACT、ZeroClaw）的 harness 达到最高性能；SFT+RL 在除 OpenClaw 外的每个 harness 上都带来大幅提升——OpenClaw 仅获得中等增益，却消耗「远长于其他的提示与上下文」。这印证了此前的结论：「更简单、更精良的工具与控制流对智能体性能至关重要」。

**（2）向未见过的 harness 泛化。** 仅在 ZeroClaw 上训练，就能在未见过的 OpenClaw（+3.3）与 Codex（+4.6）上超过未训练基线；在全部三种 harness 上联合训练则在所有基准上表现最佳，对复杂 harness 增益最大（OpenClaw +9.5，Codex +20.3），甚至将 ZeroClaw 自身的性能提升到超过仅用 ZeroClaw 训练的水平（48.5 对 46.0）。作者将其归因于多 harness 训练中看到了更多样化的工具调用与控制流。

**（3）在 SFT 之上 RL 带来了什么。** 对每检查点 100 条 ClawEval 轨迹的行为分析发现：在 ZeroClaw 上，RL 将通用 shell 工具调用从 22.6% 降到 13.9%，将调用重新分配到专用服务工具，并略微缩短了轨迹——教会模型「选用合适的专用工具，而不是退回到通用 shell」。在 Codex 上，RL 改善了错误恢复（在一条命令失败后正确完成任务）、自我验证（回读自己写入的内容加以确认）与工具覆盖。然而论文强调「即使经过 RL，错误恢复仍是最薄弱的能力」，并推测这些能力「可能需要专门的数据或训练方法来进一步加强」。

## 结论与局限

论文总结认为，OpenForge RL「使任意 harness × 任意环境都可以用 veRL 等标准 RL 代码库训练」，从而让智能体能够在真实的部署场景中直接被优化。仅凭「数百到数千个自动整理的任务」，训练出的模型就在几乎全部基准上超越了相近规模的开源模型。

**局限与开放问题：**

- 错误恢复即使在 RL 之后仍然薄弱，可能需要专门的数据来强化；
- 因环境错误产生的不完整 rollout 被简单丢弃，对「这些不完整 rollout 的更好 credit assignment（信用分配）」留待未来工作；
- 部分 harness（尤其是 OpenClaw）明显更难学习，提示 / 上下文过长；
- 论文指出并行的相关工作（Polar）提出了类似思路，但只聚焦软件工程，而本工作覆盖 claw 任务与基于视觉的 GUI 任务，横跨六个基准。

作者表示将发布代码、数据与模型，以推动基于 harness 的智能体研究。

## 与 harness × 模型训练的关系

本文的核心命题是：在真实部署 harness 上训练能从根本上减少 train–deploy 失配（train–deploy mismatch）。传统的 agent 训练管线（纯 SFT 或基于原生/简化工具接口的 RL）在训练时用的是轻量化、无状态、单进程的推理循环，而部署时则套上 Claude Code、Codex、OpenClaw 这类复杂的多进程 harness——两者之间的上下文形态、工具调用方式与控制流行为存在系统性差异，导致模型学到的策略无法在真实 harness 中完整复现。OpenForge RL 通过轻量代理把「训练环境」替换为「真实的 harness 推理」，使模型在训练阶段就看到与部署完全一致的提示结构、工具接口与控制流，同时用 Kubernetes 隔离容器把 rollout 与训练解耦以维持可扩展性。其经验证据——零样本泛化到未见 harness、多 harness 联合训练优于单 harness 训练、RL 在真实 harness 上直接改善工具选择与自我验证——说明训练时所见即部署时所得，这正是「harness × 模型」协同训练范式所追求的：让模型在它真正将要运行的环境中学习，而非在一个理想化抽象上学习。
