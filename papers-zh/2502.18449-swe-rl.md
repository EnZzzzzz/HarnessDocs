# 通过开放软件演化数据上的强化学习推进大语言模型推理（SWE-RL: Advancing LLM Reasoning via Reinforcement Learning on Open Software Evolution）
- 作者 / 机构：Yuxiang Wei（魏宇翔）、Olivier Duchenne、Jade Copet、Quentin Carbonneaux、Lingming Zhang（张令明）、Daniel Fried、Gabriel Synnaeve、Rishabh Singh、Sida I. Wang；机构：Meta FAIR（Meta 基础人工智能研究院）、UIUC（伊利诺伊大学厄巴纳-香槟分校）、CMU（卡内基梅隆大学）
- 出处：arXiv:2502.18449（已接收为 NeurIPS 2025 主会场论文）
- 原文链接：https://arxiv.org/abs/2502.18449

## 摘要（中文翻译）

近期发布的 DeepSeek-R1 展示了强化学习（reinforcement learning, RL）在增强大语言模型（large language models, LLMs）通用推理能力方面的巨大潜力。尽管 DeepSeek-R1 及其后续工作在主要方向上聚焦于将 RL 应用于竞技编程（competitive coding）和数学问题，本文提出 SWE-RL，这是首个将基于 RL 的 LLM 推理扩展至真实世界软件工程（real-world software engineering）的方法。借助轻量级的基于规则的奖励（rule-based reward，例如真值解与 LLM 生成解之间的相似度分数），SWE-RL 能够使 LLM 从海量的开源软件演化数据中自主学习、恢复开发者的推理过程与解决方案——所谓软件演化数据，即一款软件完整生命周期的记录，包括其代码快照（code snapshots）、代码变更（code changes）以及问题（issues）和拉取请求（pull requests, PR）等事件。在 Llama 3 基础上训练得到的推理模型 Llama3-SWE-RL-70B，在 SWE-bench Verified——一个由人工验证过的、包含真实世界 GitHub 问题（GitHub issues）的集合——上取得了 41.0% 的解决率（solve rate）。据我们所知，这是迄今中型规模（<100B 参数）LLM 所报告的最佳性能，甚至可与 GPT-4o 等领先的专有 LLM 相媲美。令人惊讶的是，尽管仅在软件演化数据上进行 RL，Llama3-SWE-RL 竟然涌现出了泛化的推理能力。例如，它在五个域外（out-of-domain, OOD）任务上均显示出性能提升，即函数编码（function coding）、库使用（library use）、代码推理（code reasoning）、数学（mathematics）和通用语言理解（general language understanding），而监督式微调（supervised fine-tuning, SFT）基线在平均表现上反而出现了性能下降。总体而言，SWE-RL 开辟了一条新方向：通过在海量软件工程数据上进行强化学习来提升 LLM 的推理能力。

## 核心贡献
- 提出 SWE-RL，首个专门利用软件演化数据（如 PR）与基于规则的奖励、为软件工程任务增强 LLM 的强化学习（RL）方法。
- 采用轻量级基于规则的奖励：即 LLM 生成补丁（patch）与真实 GitHub PR 中的 oracle 补丁（真值补丁）之间的相似度，从而无需执行反馈（execution feedback）或专有的教师模型（teacher model）即可开展 RL 训练。
- 构建大规模开放软件演化数据训练集：从 GHArchive 收集 2015 年 1 月 1 日至 2024 年 8 月 31 日的 GitHub 事件，克隆并处理了 460 万个仓库（4.6M repositories）的完整提交历史，聚合得到 2400 万个 PR 实例（24M PR instances），经相关文件预测与过滤后得到约 1100 万个唯一 PR 实例（~11M unique PR instances），并排除了所有 SWE-bench 相关仓库以避免数据污染。
- 基于 Llama-3.3-70B-Instruct，采用 GRPO（Group Relative Policy Optimization，组相对策略优化）进行训练，并使用 Agentless Mini 脚手架（scaffold）进行评估。
- 关键论断：仅针对问题求解（issue-solving）应用 RL，即可迁移到域外推理任务（数学、代码推理、通用语言理解）；而 SFT 基线在平均表现上反而下降。
- 最终模型 Llama3-SWE-RL-70B 在 SWE-bench Verified 上达到 41.0% pass@1，为迄今中型规模（<100B）LLM 的最优性能，可与 GPT-4o（Agentless 38.8%）等专有模型相当。

## 方法（中文翻译）

**软件演化数据构建（数据构建，2.1 节）：** 数据来源为 GHArchive 上的 GitHub 事件流，时间跨度为 2015 年 1 月 1 日至 2024 年 8 月 31 日。研究团队通过 git 克隆并处理了 460 万个仓库（含完整提交历史），再聚合成 2400 万个已合并 PR 实例——每个实例涵盖与之关联的问题、讨论、提交以及基于 merge-base（合并基）的代码上下文。随后，通过 Llama-3.1-70B-Instruct 进行相关文件预测（relevant-files prediction），并施加一系列过滤规则（去除机器人账户、空改动或过大改动、以及类 CodeLlama 的 hunk 过滤器），最终得到约 1100 万个唯一 PR 实例。所有 SWE-bench 涉及的仓库都被排除在外，以防止训练数据与评估基准之间发生污染。

**奖励设计（2.2 节）：** 对于格式不正确的回答，奖励设为 −1；否则奖励取 `compare(patch_pred, patch_gt)`，即生成补丁与真值补丁之间的相似度。`compare` 具体实现为 Python 标准库的 `difflib.SequenceMatcher`，返回 0 到 1 之间的序列相似度分数。该奖励属于纯规则式、轻量级奖励，无需执行测试或调用外部教师模型。训练输入提示中包含完整文件内容与问题文本，模型须先进行推理以定位缺陷（localize faults），再按 Agentless 格式输出 SEARCH/REPLACE 形式的编辑。

**训练设置：** 以 Llama-3.3-70B-Instruct 为基座模型，在 16000 上下文窗口下训练 1600 步；全局批大小为 512，每批从 32 个问题中各采样 16 条轨迹（rollout），每个全局步执行一次优化。策略优化采用 GRPO，使用归一化的组内奖励并对参考策略施加 KL 惩罚项。

**Agentless Mini 脚手架（第 6 节）：** 由 Agentless 简化而来——仅做文件级定位（将仓库结构映射为文件路径），将完整文件内容送入修复（repair）步骤。它生成多个候选位置集合与修复样本，并在检索到测试文件的引导下生成复现测试（reproduction tests），再通过投票选出多个得分最高的样本。重排序（reranking）阶段综合使用回归测试（使现有失败用例最小化）与 CodeT 风格的双执行一致性投票：共识组按 `|P| × |T|²` 打分（P 为补丁集合、T 为测试集合）。

## 实验结果

**SWE-bench Verified 主结果（表 1）：** Llama3-SWE-RL-70B 在 Agentless Mini 脚手架下达到 **41.0% pass@1**，为 ≤100B 参数模型中的最优。对照点：SWE-Gym-32B 为 32.0，SWE-Fixer-72B 为 30.2，Lingma-SWE-GPT-72B 为 28.8；而 GPT-4o + Agentless 为 38.8，o1-preview 为 41.3，DeepSeek-R1 为 49.2（均属于 >100B 或专有模型）。评估设置：每个问题生成 500 个补丁（温度 1.0），取前 30 个复现测试用于执行与重排序，提交排名最高的补丁。

**仅修复（repair-only）基线（表 2）：** Llama-3.3-70B-Instruct 贪心解码为 5.4，多数投票为 16.6；Llama3-SWE-SFT-70B 贪心解码为 29.6；**Llama3-SWE-RL-70B 贪心解码为 34.8**，为最优修复性能（格式准确率略低于 SFT：95.6% 对 96.2%）。

**规模扩展（图 5）：** 修复样本数从 20 增至 160 时，性能从 33.6 提升至 40.0，在 320–500 样本时趋于 41.0；复现测试数带来渐进提升（38.8 → 41.0，直至 20 个测试），20 与 30 个测试之间无明显差异。

**涌现的通用推理能力（2.3 节，图 4）：** 在软件工程场景中观察到"aha 时刻"：自我反思（如"let me reconsider"，重新考虑）、主动探索替代方案、以及分而治之（divide-and-conquer）策略——"这一行为是模型与 RL 相互作用过程中自然涌现的，而非被显式编程出来的"。域外零样本贪心结果（表 3）：HumanEval+ 为 **79.9**（基座 76.2，SFT 73.2）；CRUXEval-I 为 **71.6**、CRUXEval-O 为 **75.5**；MATH（严格模式）为 **73.7**（基座 63.2，SFT 54.0）；MMLU 为 **86.82**；BigCodeBench-Hard 与基座持平（28.4/29.1），而 SFT 出现下降。

**奖励消融（3.6 节）：** 连续 difflib 奖励的修复得分为 34.8；离散精确匹配奖励（exact-match reward）的修复得分仅为 29.0。论文指出，离散奖励会长期停留在接近零的水平，因为"真实世界的补丁高度多样化，往往难以被精确匹配"。

## 结论与局限

**结论：** SWE-RL 是首个利用软件演化数据改进 LLM 软件工程能力的强化学习方法，在中型模型上取得了最先进（state-of-the-art, SOTA）的性能，"与 GPT-4o 等许多专有 LLM 相当"，同时在泛化推理能力上也有提升。它开辟了"通过在海量软件工程数据上进行强化学习来提升 LLM 推理能力"的新方向。

**局限：**
- 奖励比较的是序列相似度（sequence similarity）而非语义等价性，"这可能妨碍策略 LLM 探索功能等价的替代解决方案"。
- Agentless Mini 的定位步骤过于简化（仅做仓库结构 → 文件路径的映射），"缺乏全面的上下文信息"。
- 作为流水线式（pipeline-based）方法，各步骤被拆分为独立推理阶段，因此模型"无法通过交互反馈进行学习"，也无法从整体上统筹考虑问题。
- 需要较大的采样预算，"对于执行成本较高的项目可能并不实用"。

**未来工作：** 引入智能体式强化学习（agentic RL），使模型联合学习定位与修复；纳入执行环节以实现与环境的直接交互；以及提升采样效率。

## 与 harness × 模型训练的关系

SWE-RL 的核心启示在于：强化学习直接作用于"agent 的推理过程"本身——模型通过大规模软件演化数据学习到的不是某一技能的机械复现，而是自我反思、多步推理、方案探索等通用能力，这些能力会自动迁移到定位缺陷、编写补丁乃至域外数学与语言任务上。这意味着在 harness 与模型训练的配合中，训练侧的目标不应只是"教会模型完成任务 X"，而是通过 RL 塑造模型在工具调用、失败重试、分支取舍时的决策质量；而 harness 侧则应为模型提供充分的探索空间（如 SWE-RL 中 Agentless Mini 的位置/补丁多候选采样与投票重排序机制），把 RL 训练好的"自主性"转化为端到端的任务成功率。反过来，harness 中诸如执行反馈、测试选择等结构化信号，亦可作为更细粒度的奖励来源回传给 RL 训练，形成"训练提升 agent 能力、harness 释放 agent 能力"的正向循环。
