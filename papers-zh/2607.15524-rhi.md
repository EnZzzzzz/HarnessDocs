# 递归式 Harness 自我改进（Recursive Harness Self-Improvement, RHI）

- 作者 / 机构：Hyunin Lee、Jinglue Xu、Jeffrey Seely、Donghyun Lee、Matei Zaharia、Yujin Tang（Sakana AI 与 UC Berkeley，加州大学伯克利分校）
- 出处：arXiv:2607.15524 [cs.LG]，2026-07-17 提交（v1）；Subjects: cs.LG / cs.AI
- 原文链接：https://arxiv.org/abs/2607.15524

## 摘要（中文翻译）

在「模型–harness 共同演化」（model–harness co-evolution）的范式下，harness（推理框架 / 智能体外壳）不仅是推理时的脚手架，更是「数据生成组件」，其执行轨迹（execution trace）能够塑造未来的基础模型。这催生了「harness 在环学习」（harness-in-the-loop learning）：同时以智能体即时性能与用于未来模型训练的轨迹质量为优化目标来改进 harness。然而，持续更新由提供商构建的脚手架（provider-built scaffolds）代价高昂且劳动密集。因此本文研究：以任务特定的方式优化用户自行构建的 harness，能否在保持计算轻量、仅需少量更新迭代的同时，提升执行轨迹的质量。为此，作者提出**递归式 Harness 自我改进**（Recursive Harness Self-Improvement, RHI）——将 harness 表示为 agent 循环的 prompt 级规格说明（prompt-level specification），并利用其自身修订历史的成对反馈（pairwise feedback）对其进行迭代精炼。在横跨量化金融、机器人、制药的 30 个合成机器学习研究任务上，少数几次 RHI 迭代就足以大幅提升低推理算力（low-reasoning-effort）智能体的性能上限，超过对应的最高推理算力（maximum-reasoning-effort）设置，同时将推理成本最高降低 60%。作者证明，这些收益主要来自更有效的智能体间信息流（inter-agent information flow）所驱动的、任务特定的上下文管理（context management）改善，而非更长的推理轨迹。最后，作者将此行为形式化为关于 RHI 隐式优化目标的一个信息论假设（information-theoretic hypothesis），从而将 RHI 定位为「模型–harness 共同演化」范式下进行持续学习（continual learning）的一种实用算法。

## 核心贡献

- **任务特定的用户构建 harness 优化**：证明用户自行构建的、prompt 级的 harness 可以按任务特定方式被优化，从而在不更新提供商脚手架的前提下改善执行轨迹质量。
- **RHI 方法**：把 harness 表示为一个 agent 循环的 prompt 级规格（角色、指令、契约、跳跃步骤、辅助规则），并基于其自身修订历史的成对反馈进行迭代精炼，每次迭代仅需一次新的智能体执行加一次成对评估（Θ(1) 开销）。
- **抬升推理算力扩展上限**：在 30 个合成 ML 研究任务上，少数迭代就让低推理算力智能体（Sonnet 4.6 / Opus 4.7 / Opus 4.8 的 high 档）在成对比较中超过对应最高算力设置（max / xhigh / ultracode），其中 Opus 4.8 的 high+ℋ[2] 甚至超过提供商内置的动态多智能体工作流。
- **推理成本最高降低 60%**：伴随显著的 cache 读写下量（如 Opus 4.8 上较 ultracode 档低 64%）。
- **机制归因**：收益主要来自任务特定的上下文管理——通过契约对智能体间信息流施加任务依赖的稀疏模式，而非更长的推理输出。
- **信息论形式化**：把 RHI 的隐式更新目标形式化为最大化任务相关信息、同时最小化任务条件冗余（total correlation）的假设，为「模型–harness 共同演化」范式下的持续学习提供了一个实用算法。

## 方法（中文翻译）

### 问题设定

一个编码智能体 A（固定的语言模型 L）在 harness H 之下，从任务提示 x 产出代码仓库 y。理想目标是找到一个任务特定的 harness，使其在 LLM 评判者（LLM-as-a-judge）的成对比较中，对竞争 harness 的期望胜率（win rate）最大化。已有的方法——包括基于种群搜索（population-based search）的（Meta-Harness、AutoHarness、TTHE、ADAS、GPTSwarm、AFlow、AlphaEvolve、ShinkaEvolve）与 prompt 优化器（OPRO、TextGrad、DSPy、GEPA）——都需要对每个候选做昂贵的黑盒智能体执行，不适合按任务逐例优化用户 harness。

### 把 harness 表示成 prompt 级对象

RHI 的关键设计选择是把 harness 当作 prompt 级对象而非可执行代码。它规定了：

- **智能体设计（agent design）**：候选智能体的角色（roles）与指令（instructions）；
- **智能体工作流（agent workflow）**，进一步分解为：
  - **契约（contracts）**：子智能体（subagent）与编排器（orchestrator）之间交换的信息规格；
  - **跳跃步骤（hops）**：交互结构 / 编排器与子智能体之间的工作流步骤；
- **辅助规则（auxiliary rules）**：验收门控（acceptance gates）、失败回退规则（failure fallback）、召回触发（recall triggers）。

### 轨迹局部的自我比较（trajectory-local self-comparison）

与对整个种群做比较不同，RHI 只把每个新 harness 的输出与其直接前驱（immediate predecessor）的缓存输出做比较：每次迭代只需一次新的智能体执行 + 一次成对评估（Θ(1) 开销，而理想目标为 Θ(M²)、种群搜索为 Θ(m²)）。

### 少量迭代 + 累积偏好历史

历史 D_x^(i) = {连续两次修订之间评判者的判断} 作为「动量语义信号」（momentum-semantic signal）引导 harness 修订：

> H_x^(i+1) = L_harness(H_x^(i), D_x^(i))

harness 优化器从不直接看到评估提示 x_eval，只看到累积的成对反馈历史——因此 RHI 是朝向一个隐式偏好目标进行的「递归自我改进」。

### 为什么优先改进工作流而非智能体设计

作者假设：任务特定的契约与跳跃步骤通过上下文管理来提升性能与效率。契约对智能体间信息流施加「任务依赖的稀疏模式」——类似于稀疏注意力（sparse attention）之于稠密全连接（dense all-to-all）。每个智能体只对所需信息做条件化（conditioning），而非对整个交互历史做条件化，从而减少冗余的上下文传播、改善 KV 缓存（KV-cache）效率。

## 实验结果

### 基准与设置

- 30 个合成的开放式 ML 研究任务，来自量化金融、机器人、制药各 10 个，由真实行业招聘启事转化为研究风格提示；每个任务要求产出完整的代码仓库，含标准化交付物：research_report.md、.png 可视化、metrics.json、index.json。
- 评估采用 LLM 成对评判，覆盖 6 项标准：交付物覆盖、严谨性、可复现性、呈现质量、工程质量、任务对齐。
- 基础智能体：Claude Sonnet 4.6、Opus 4.7、Opus 4.8，均为 high 推理算力；基线为同一模型的 xhigh、max（对 Opus 4.8 还有 ultracode）推理档位；RHI 仅作为 prompt 增强施加于 high 档智能体。评估者配置包括两种（sonnet-4.6 / opus-4.8）与六种（opus-4.7），各 3 个随机种子。

### 要点 1：少量样本的 RHI 抬升了测试时扩展（test-time scaling）上限

- **Sonnet 4.6**：2 次迭代后，high+ℋ[2] 在 30 组成对比较中赢下 20 组、胜过 sonnet-4.6-max；第 3–4 次迭代增益持续。
- **Opus 4.7**：ℋ[0] 不及 xhigh/max，但**单次 RHI 迭代**即同时超过两者。
- **Opus 4.8**：ℋ[0] 略胜 / 追平 xhigh；2 次迭代后 ℋ[2] 超过包括 xhigh、ultracode、max 在内的全部基线。
- 值得注意：opus-4.8-high+ℋ[2] 超过了 opus-4.8-ultracode（后者使用提供商内置的动态多智能体工作流）。作者将其解释为：任务特定的、用户构建的 prompt 级 harness 可以击败固定的、系统级的提供商 harness。

### 要点 2：收益并非来自更长的输出

- Sonnet 4.6 与 Opus 4.8：归一化输出 token 数在各迭代间几乎持平（分别约 1.71–1.86 与 1.42–1.81），性能却在提升。
- Opus 4.7：证据不具决定性（仅 2 次迭代，token 与性能同升）。

### 要点 3：通过降低 cache 读写实现成本效率

- **Sonnet 4.6**：ℋ[2] 成本 2.38 vs. max 2.56（低 7%）；cache 读写下降低 33%（4.91 → 3.31）。
- **Opus 4.7**：ℋ[1] 成本 2.11 vs. max 2.60（低 18%）；cache 读写下降低 37%（3.37 → 2.11）。
- **Opus 4.8**：ℋ[2] 成本 1.69 vs. max 2.19（低 23%），vs. ultracode 4.15（**低 60%**）；cache 读写下降低 32%（对 max）、64%（对 ultracode）。

### 消融与分析

- **与训练时扩展互补而非替代**：RHI 在 sonnet-4.6-high 上提升显著（2–4 次迭代后趋于平台期），但并未弥合与 opus-4.7-high/xhigh 基线的差距——RHI 补充而非替代更强的基座模型。
- **组件演化**：对 harness 组件（角色、指令、契约、跳跃步骤）做 t-SNE/UMAP 嵌入发现——契约在三个领域都呈现最清晰的任务依赖聚类；跳跃步骤与指令呈中等聚类；角色最不可分（共享数据准备、模型训练等高层角色）。余弦相似度上，契约快速稳定（0.48 → 0.66 → 0.69 → 0.72）；首次 RHI 更新是语义变化最大的一步（ℋ[0]→ℋ[1] 相似度 0.82，此后各步为 0.97–0.99）。
- **隐式目标假设**：J(g_i) = f_ext − β·f_int。其中 f_ext 是外部强调组件类型（契约、跳跃步骤）的组件嵌入与任务身份之间的平均互信息（mutual information, MI）；f_int 是全部 harness 组件表示上的任务条件总相关（total correlation, TC），衡量冗余。直觉是：仅最大化任务信息会得到组件冗余重复同一内容的退化解，冗余惩罚则鼓励模块化分解（角色定义专长、指令定义行为、契约定义通信、跳跃步骤定义控制流）。

## 结论与局限

作者的核心论证是：未来 harness–模型共同演化的进展，应当通过优化用户构建的、任务特定的 harness 来改进「数据飞轮」（data flywheel）——即执行轨迹的生成质量。RHI 被定位为一个实用框架，用于把编码智能体持续特化到多样化的开放式任务上。

**局限：**

1. 嵌入分析是「相关性而非因果性」（correlational rather than causal）——编码智能体是黑盒，文本嵌入只是语义变化的外部代理。
2. RHI 不替代训练时扩展（train-time scaling）：在较弱模型上的增益无法弥合与较强模型的差距，「为进一步的算法改进留出空间」。
3. Opus 4.7 的输出 token 证据不具决定性（仅两次迭代）。
4. 隐式目标假设「是一个合理的目标函数」（a plausible objective function），作为可检验的解释提出，而非被证实的机制。
5. 更强模型上更大的成本节省不应解读为 RHI 随模型质量提升而更有效；更保守的解读是：强模型上的测试时计算扩展收益递减。

## 与 harness × 模型训练的关系

RHI 与 harness 项目（EZAgent / HiAgent）关注的是同一条「模型–harness 共同演化」反馈闭环的两端：本论文处理的是该闭环的前半段——优化 harness 以生成更高质量的、可用于未来训练的执行轨迹；而 harness × 模型训练（如 OpenForge RL 式的端到端训练）处理的是后半段——把 harness 的推理过程本身作为训练环境来微调模型。两者互为补充：RHI 以近乎零的训练开销，仅靠 prompt 级规格与自身修订历史的成对反馈，就能把低推理算力智能体的性能天花板抬到最高算力设置之上并降低最高 60% 的推理成本，为在 EZAgent / HiAgent 这类 harness 上运行的智能体提供了一种「任务特定上下文管理」的轻量增强手段；其信息论假设（最大化任务相关信息、最小化组件冗余）也为「如何在训练时把上下文形态、契约与信息流设计得更利于模型学习」提供了指导。
