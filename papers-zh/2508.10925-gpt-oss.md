## 摘要（中文翻译）

我们发布 gpt-oss-120b 与 gpt-oss-20b 两个开源权重（open-weights）推理模型，它们把准确性与推理成本的边界向前推进了一大步。两个模型采用高效的专家混合（Mixture-of-Experts, MoE）Transformer 架构，并使用大规模蒸馏（distillation）与强化学习（reinforcement learning）进行训练。我们针对强智能体能力（agentic capabilities）对模型做了优化——包括深度研究式的浏览、Python 工具使用，以及对开发者自定义函数的支持——同时采用一种渲染后的对话格式（rendered chat format），从而实现了清晰的指令遵循与角色划分。两个模型在数学、编码与安全等一系列基准上均取得了强劲成绩。我们以 Apache 2.0 开源协议发布模型权重、推理实现、工具环境与分词器（tokenizer），以促进广泛使用与后续研究。

## 核心贡献

- **发布 OpenAI 自 GPT-2（2019）以来首批 GPT 类开放权重模型**：gpt-oss-120b 与 gpt-oss-20b，全部以 Apache 2.0 协议开源，包括权重、推理实现、工具环境与分词器。
- **高精度 / 低成本的前沿权衡（Pareto 前沿）**：在开源权重模型上把精度与推理成本推到新的平衡点；120b 可在单张 80GB GPU 上运行，20b 可在约 16GB 显存的设备上运行。
- **高效的 MoE 架构**：以远小于同能力稠密模型的激活参数量（120b 每 token 仅激活 5.1B 参数）达到接近闭源 o3/o4-mini 级别的推理能力。
- **训练方法创新**：采用"大规模蒸馏 + 强化学习"（distillation + RL）而非传统的纯 SFT 后训练；后训练与 OpenAI o3 类似的链式思考（Chain-of-Thought, CoT）RL 技术，教会模型推理、问题求解与工具使用。
- **强智能体能力**：原生支持浏览工具、有状态的 Python（Jupyter）工具执行、任意开发者自定义函数，并可在 CoT、工具调用与最终答案之间自由交错。
- **Harmony 对话格式**：以自定义 token 与关键字参数渲染 System/Developer/User/Assistant/Tool 角色层级，并通过 analysis（思维链）、commentary（工具调用说明）、final（面向用户答案）三个可见性通道区分内容，实现清晰的指令遵循与角色划分。
- **安全对齐**：采用 deliberative alignment（审慎对齐）进行安全训练；官方 Preparedness 评估确认默认模型在生物/化学、网络、AI 自我改进等类别上均未达到"高能力（High capability）"提示性阈值。

## 训练方法（中文翻译）

### 架构

两个模型均为自回归专家混合（MoE）Transformer，沿用 GPT-2/GPT-3 的设计风格：

| 模型 | 总参数 | 每 token 激活参数 | 层数 | 每 MoE 层专家数 | 每 token 激活专家数 |
|---|---|---|---|---|---|
| gpt-oss-120b | 116.8B | 5.1B | 36 | 128 | 4（top-4） |
| gpt-oss-20b | 20.9B | 3.6B | 24 | 32 | 4（top-4） |

- 残差流（residual stream）维度 2880；Pre-LN 布局，激活用 RMSNorm。
- MLP 使用带截断（clamping）与残差连接的 Gated SwiGLU。
- 注意力：交替使用带宽 128 的带状窗口（banded-window）与稠密（dense）注意力模式；64 个 query 头、维度 64；采用分组查询注意力（Grouped-Query Attention, GQA），8 个 KV 头；旋转位置编码（RoPE）；使用 YaRN 将上下文扩展至 131,072 tokens；每个注意力头带可学习的 softmax 分母偏置。
- **量化**：MoE 权重经后训练量化为 MXFP4（约 4.25 bits/参数），使 120b 模型可装入单张 80GB GPU、20b 模型约 16GB 显存即可运行；检查点大小分别为 60.8 GiB 与 12.8 GiB。
- **分词器**：o200k_harmony BPE（o200k 的超集），词表 201,088，已随 TikToken 一并开源。

### 预训练（Pretraining）

- 纯文本（text-only）数据集，规模达数万亿 token，聚焦 STEM、编码与通用知识。
- 复用 GPT-4o 的 CBRN（化学/生物/放射/核）预训练过滤，对有害内容（尤其是危险生物安全知识）进行过滤。
- 知识截止时间：2024 年 6 月。
- 基于 NVIDIA H100 GPU，使用 PyTorch 与面向专家优化的 Triton kernel 训练，并采用 Flash Attention；gpt-oss-120b 消耗约 210 万 H100 机时，gpt-oss-20b 约少近一个数量级。

### 后训练：CoT 强化学习（Post-training: CoT RL）

官方模型卡将后训练概括为"与 OpenAI o3 类似的 CoT RL 技术"，用于教会模型推理、问题求解与工具使用；摘要中则明确为"大规模蒸馏与强化学习"。报告中**未**披露诸如 GRPO（Group Relative Policy Optimization）、cooldown（冷却）/critical-SFT 阶段、拒绝采样自生成数据等细粒度阶段配方——这些细节并不在本技术报告公开范围之内（详见"结论与局限"）。报告公开的后训练要点如下：

- **推理强化学习**：通过 RL 优化模型的链式思考过程，使其在生成最终答案前先进行显式推理，从而提升数学、科学、编码等任务的求解能力；这一做法与 o3 系列一脉相承。
- **完整的、不被直接监督的 CoT**：OpenAI 刻意不对思维链进行过滤或隐藏（不施加直接监督），认为透明的推理轨迹便于用户调试与安全监控；但报告同时提示 CoT 中可能包含幻觉内容，不应未经处理直接展示给用户。
- **蒸馏与 RL 结合**：后训练综合了大规模蒸馏（对强模型轨迹的学习）与强化学习，而非仅依赖人工标注，这与"自生成数据 + RL 自我提升"的思路一致（即模型自身产生的推理数据驱动后续 RL 改进）。

> **第三方技术综述补充（IntuitionLabs《GPT-OSS: A Technical Overview…》，非官方报告原文）**：技术综述将后训练对齐描述为两个阶段——首先是包含人类示范/指令的监督微调（Supervised Fine-Tuning, SFT）阶段，随后是高算力的强化学习阶段，类似于基于人类反馈的强化学习（RLHF）；对齐目标遵循 OpenAI Model Spec 的 helpfulness（有用性）与 safety（安全性）要求，并教会模型高级推理策略（如 CoT）与工具使用。该综述同样未披露 GRPO/cooldown 等细节配方。

### Harmony 对话格式与工具使用训练

- **Harmony chat format**：引入自定义 token 与关键字参数（User/Assistant）的渲染对话格式；角色 System/Developer/User/Assistant/Tool，优先级层级为 System > Developer > User > Assistant > Tool。通过通道（channels）标记内容可见性：`analysis`（思维链，CoT）、`commentary`（工具调用说明）、`final`（面向用户的最终答案）。多轮对话时应移除历史推理轨迹。实现见 github.com/openai/harmony。
- **可变推理努力（variable-effort reasoning）**：提供低/中/高三个推理档位，通过系统提示词关键字（如 "Reasoning: low"）设置；档位越高，平均 CoT 长度越长，呈现平滑的测试时扩展（test-time scaling）。
- **智能体工具训练**：内置浏览工具（搜索/打开网页）、Python 工具（有状态的 Jupyter 环境），以及通过 Developer 消息中的 schema 传入的任意开发者自定义函数；模型可在一次响应中交错进行 CoT、工具调用与最终作答。这与任务所述的"agent/工具使用"重点直接对应——模型被明确训练成"先想、再查/算、后答"的智能体循环。

### 安全训练

- 采用 OpenAI 的 o 系列 RL 技术栈进行对抗训练（adversarial training）：以"仅有用（helpful-only）"RL 加领域特异性"能力最大化"RL（如生物风险数据、CTF 环境）探测模型是否可能在生物、化学或网络领域达到高能力，结论为未达到。
- 外部评审（METR、SecureBio、Daniel Kang）给出 22 条建议，其中 11 条被采纳（12 条"高优先级"项中落实了 9 条）。

## 实验结果

（均为高推理档位，除特别注明）

### 推理与知识（无工具）

| 基准 | gpt-oss-120b | gpt-oss-20b |
|---|---|---|
| AIME 2024 | 95.8 | 92.1 |
| AIME 2025 | 92.5 | 91.7 |
| GPQA Diamond | 80.1 | 71.5 |
| HLE（Humanity's Last Exam） | 14.9 | 10.9 |
| MMLU | 90.0 | 85.3 |

### 编码与工具使用

- SWE-bench Verified：120b **62.4**，20b **60.7**
- Codeforces Elo（高档、无工具）：120b 2463，20b 2230；带工具：120b **2622**，20b 2516
- Tau-Bench Retail：120b 67.8，20b 54.8
- Aider Polyglot：120b 44.4，20b 34.2

### 健康医疗（HealthBench：总体 / Hard / Consensus）

- gpt-oss-120b：57.6 / 30.0 / 89.9 ——"与 OpenAI o3 几乎持平"（o3 约 59.8 / 31.6）
- gpt-oss-20b：42.5 / 10.8 / 82.6 ——"略优于 OpenAI o1"

### 多语言（MMMLU 平均）

- gpt-oss-120b：81.3；gpt-oss-20b：75.7（对比 o4-mini 85.2、o3 88.8）

### Preparedness（能力边界）评测

- **生物**：经对抗微调的 120b 在文本生物风险问答上较强，但"在复杂协议调试类任务上尚未达到高能力提示性阈值"，且在 ProtocolQA、Tacit Knowledge、TroubleshootingBench 上低于共识专家基线（专家 80 分位 = 36.4%）。DeepSeek R1-0528、Qwen 3 Thinking、Kimi K2 等竞品开源模型与之相当或接近，因此该发布"并未显著推进该领域的最先进水平"。
- **网络（Cyber）**：CTF 与 Cyber Range 结果"与 OpenAI o3 相当，同样低于我们的高能力阈值"；没有任何模型能在无提示或带提示情况下独立解开 Cyber Range 场景。
- **AI 自我改进**：gpt-oss 模型在 SWE-bench Verified、OpenAI 内部 PR 数据集、PaperBench 上均未超过 o3/o4-mini。

### 安全评测（Safety Evaluations）

- **违规内容**：标准评测接近饱和；在更难的 Production Benchmarks 上 gpt-oss 模型整体"显著优于 OpenAI o4-mini"，但 20b 在 illicit/violent 类别上略逊于 o4-mini。
- **越狱（StrongReject）**：各危害类别上"总体与 OpenAI o4-mini 表现相近"。
- **指令层级（instruction hierarchy）**：两个 gpt-oss 模型"总体不及 OpenAI o4-mini"——例如系统提示词提取 0.832（120b）对 0.993（o4-mini）；短语保护 0.912 对 0.937。
- **幻觉（SimpleQA/PersonQA）**：不及 o4-mini，符合更小模型的预期。
- **公平性/偏见（BBQ）**：与 o4-mini 大致持平。
- **思维链幻觉**：对 CoT 无直接优化压力，因此保持可监控性；但 CoT 可能包含幻觉内容，不应未经过滤直接展示给用户。

## 结论与局限

### 结论

gpt-oss-120b / gpt-oss-20b 是面向智能体工作流（agentic workflows）优化的一对开源权重推理模型：以 MoE 架构 + 蒸馏与强化学习后训练，在数学、编码、工具使用、健康与多语言等基准上逼近甚至个别项超过 OpenAI 闭源 o3/o4-mini 的水平，同时以 MXFP4 量化把部署成本压缩到单卡 80GB / 16GB 即可运行。以 Apache 2.0 协议发布权重、推理实现、工具环境与分词器，标志着 OpenAI 自 GPT-2 以来最大规模的开放动作，意在促进广泛使用与社区研究；模型作为"模型卡（model card）"而非"系统卡（system card）"发布，是因为其将被部署到众多利益相关方各自维护的系统中。

### 局限（官方报告所列）

1. **纯文本架构**：无法处理湿实验（wet-lab）与视觉/图像类上下文，在解读显微镜图像、仪器图表等场景受限。
2. **规模带来的能力缺口**：更小的模型幻觉更多、世界知识更少（SimpleQA/PersonQA 均不及 o4-mini）。
3. **开放权重的双重性**：攻击者可对权重进行微调以绕过拒答，开发者"需要实施额外的防护措施"。
4. **指令层级鲁棒性**：落后于 o4-mini，针对系统消息的越狱防御较弱。
5. **CoT 可监控但不可信**：思维链未经直接监督、保持透明，但可能包含幻觉内容。
6. **用途声明**：模型"不适用于疾病的诊断或治疗"。
7. **配方透明度**（译者补充）：本报告为模型卡层面，未披露 GRPO、cooldown/critical-SFT、拒绝采样自生成数据等细粒度训练配方；需要该级配方的研究者应参照 OpenAI o 系列方法论及 DeepSeek-R1 等公开报告。

## 与 harness × 模型训练的关系

gpt-oss 报告是 harness（工具/智能体运行环境）项目做模型训练的关键参考基线与配方来源：其一，它给出了一条"预训练 + CoT RL 后训练 + 大规模蒸馏"的可复现主线，明确以"思维链 + 工具调用交错"为训练目标，这正对应 harness 项目中 agent 需要"先推理、再调工具、后作答"的行为模式——报告中的 Harmony 格式（analysis/commentary/final 通道）与浏览/Python/自定义函数三件套，可作为 harness 训练数据格式与工具 API 设计的直接蓝本。其二，它示范了如何在不开源配方细节的情况下，把训练信号集中到工具使用与推理强化上（自生成数据驱动的 RL 自我提升），为 harness 团队用自家工具轨迹做 RL 提供了可对标的能力指标（SWE-bench、Tau-Bench、Codeforces）与基线模型（120b/20b，含 MoE 激活参数与量化部署方案）。其三，模型卡对开放权重安全与指令层级的讨论，也提示 harness 项目在引入开源基座时需自行补齐拒答防护与指令层级加固。
