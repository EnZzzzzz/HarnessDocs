# s1：简单的测试时缩放（s1: Simple Test-Time Scaling）
- 作者 / 机构：Niklas Muennighoff、Zitong Yang、Xiang Lisa Li、Li Fei-Fei、Percy Liang、Emmanuel Candès、Tatsunori Hashimoto（斯坦福大学 Stanford University）；Weijia Shi、Hannaneh Hajishirzi、Luke Zettlemoyer（华盛顿大学 University of Washington）；另有作者隶属 Allen Institute for AI（Ai2）与 Contextual AI
- 出处：arXiv:2501.19393（v3，2025-01-31 提交）；发表于 ICLR 2025 Workshop (LLM_Reason_and_Plan)
- 原文链接：https://arxiv.org/abs/2501.19393

## 摘要（中文翻译）

测试时缩放（test-time scaling）是一种很有前景的语言建模新方法，它利用额外的测试时计算量（test-time compute）来提升性能。OpenAI 的 o1 模型展示了这种能力，但并未公开分享其方法，由此催生了许多试图重建并改进它的工作。本文提出了最简单的有效的测试时缩放方案，并用它打造了 s1——一个强大的推理模型。我们证明：在一个小型、精心筛选的数据集（s1K）上进行简单的监督微调（supervised fine-tuning，SFT），即可赋予模型强烈的测试时缩放行为，并在广泛的任务上获得有竞争力的性能。s1K 包含 1,000 道按照难度（difficulty）、多样性（diversity）与质量（quality）三个标准精心挑选的问题，并配以一个先进推理模型（Gemini Thinking API）生成的推理轨迹（reasoning trace）。我们还开发了预算强制（budget forcing）方法，通过强行终止模型的思考过程，或在模型试图过早结束推理时追加"Wait（等等）"来延长思考，从而控制测试时计算量。这使得我们能够对 s1 的测试时计算量进行缩放，并针对具体任务调整其性能。借助 s1K、budget forcing 以及经过微调的 Qwen2.5-32B-Instruct 模型，s1-32B 在竞赛数学题（MATH 与 AIME24）上以最高 27% 的幅度超越 o1-preview。我们的方法还允许我们在不进行测试时干预的情况下超越模型自身的性能表现，将 AIME24 上的成绩从 50% 外推到 57%。模型、数据与代码将全部开源。

## 核心贡献

- **提出最简测试时缩放配方**：1,000 个精心挑选的样本做 SFT + budget forcing 干预，即可获得强推理能力与可扩展的测试时行为，无需大规模强化学习（RL）或奖励模型。
- **s1K 数据集**：从 59,029 道初始问题（16 个来源）中筛选出 1,000 道，配以 Gemini Flash Thinking API 生成的推理轨迹；用消融实验验证了难度、多样性、质量三准则缺一不可。
- **budget forcing（预算强制）**：一种解码时干预，可同时控制思考 token 的最大值与最小值——超限时强制插入 end-of-thinking（思考结束）分隔符截断思考；不足时抑制该分隔符并追加"Wait"，促使模型反思并自我纠错。
- **s1-32B 模型**：在 Qwen2.5-32B-Instruct 上以 s1K 做 SFT，仅用 16 块 NVIDIA H100、约 26 分钟即完成微调；以 1,000 样本超越 o1-preview 最高 27%，是极具样本效率（sample-efficient）的开放推理模型。
- **顺序扩展优于并行扩展**：串行增加思考预算（budget forcing）比并行多数投票（majority voting）更能提升推理表现。

## 方法（中文翻译）

**s1K 数据集构建（两阶段）**：初始收集 59,029 道题，来自 16 个数据源，遵循质量、难度、多样性三项原则。主要来源包括 NuminaMATH（30,660 道数学题）、历史 AIME 题（1983–2021）、OlympicArena（4,250 题，覆盖天文、生物、化学、计算机、地理、数学、物理）、OmniMath（4,238 题）、AGIEval（2,385 题，含 SAT/LSAT 等），以及自建的 s1-prob（182 道斯坦福统计系博士资格考试概率题）与 s1-teasers（23 道量化交易面试脑筋急转弯）。每道题用 Google Gemini Flash Thinking API 生成推理轨迹与解答，并做去污染处理——用 8-gram 对评估题（MATH500、GPQA Diamond、AIME24）进行去污染并去重。

筛选到 1,000 个样本，历经三个过滤阶段：
- **质量（quality）**：剔除 API 报错样本（59K → 54,116）与格式问题样本（→ 51,581）。
- **难度（difficulty）**：用 Qwen2.5-7B-Instruct 与 Qwen2.5-32B-Instruct 两个模型做题，移除任一模型能正确解答的问题（→ 24,496）；同时把推理轨迹的 token 长度作为难度指标。
- **多样性（diversity）**：用 Claude 3.5 Sonnet 按美国数学会 MSC（Mathematics Subject Classification）分类体系给问题打领域标签，再从 24,496 道题中按"均匀随机选领域 → 按偏向长推理轨迹的分布抽样"的方式选出 1,000 题，最终覆盖 50 个领域。

关键结论：把难度、多样性、质量联合纳入选择算法很重要；在全部 59K 样本（s1K 的超集）上训练，相比 1K 精选并无实质性增益。

**budget forcing（预算强制）**：一种简单的解码时干预，可同时控制最大和最小思考 token 数：
- **上限控制**：当思考 token 超过预算时，"通过追加 end-of-thinking token 分隔符强行终止思考过程"，让模型输出当前答案。
- **下限控制**："抑制 end-of-thinking token 分隔符的生成，改为追加 'Wait'"——阻止模型结束思考，迫使其继续反思，模型往往会自我纠错（文中给出模型从错误答案"…is 2."自我纠正的实例）。

对比基线包括 token 级/步级/类别级的条件长度控制提示词，以及拒绝采样（rejection sampling，作为长度条件后验的 oracle）。三个评估指标为：**Control**（实际计算量落在预设 [min, max] 区间的比例）、**Scaling**（分段线性函数的平均斜率，必须为正才有用）、**Performance**（达到的最高准确率）。

**训练设置**：在 Qwen2.5-32B-Instruct 上用 s1K 做监督微调（SFT），"用 PyTorch FSDP 在 16 块 NVIDIA H100 GPU 上仅 26 分钟完成"。评估基准为三个推理基准：**AIME24**（30 道 2024 年美国数学邀请赛题，答案为 000000–999999 的整数）、**MATH500**（500 道竞赛数学题）、**GPQA Diamond**（198 道博士级科学题，对应领域博士仅能达到 69.7%）。

## 实验结果

- **超越 o1-preview 最高 27%**：s1-32B 在竞赛数学（MATH 与 AIME24）上超过 o1-preview 最高 27%（AIME24 上 56.7 vs 44.6；MATH500 上 93.0 vs 85.5），并接近其蒸馏来源 Gemini 2.0 Thinking（AIME24 56.7 vs 60.0），说明蒸馏流程有效。
- **budget forcing 外推：AIME24 从 50% 提升到 57%**：借助预算强制增加测试时计算量，可在不进行测试时干预的基线表现（50%）之上继续外推（57%）；对应 Figure 1 中最右侧数据点 f(7320)=57%，即 7,320 个思考 token 时准确率 57%。
- **关键模型对比（Table 1 关键数据）**：

  | o1-preview | N.A. | 44.6 | 85.5 | 73.3 |
  | o1-mini | N.A. | 70.0 | 90.0 | 60.0 |

- **样本效率**：仅用 1,000 样本即显著超过同类的 Sky-T1（17K 样本）并接近 Bespoke-32B（17K 样本），被称"最具样本效率的开放数据推理模型"。论文坦言 r1-32B 更强，但用 1,000 样本能否达到其水平是开放问题（r1-32B 用了约 800 倍推理样本）。
- **数据选择消融**：随机选、只选最长轨迹、或只选最多样化的样本，"平均导致 AIME24 上约 −30% 的显著性能下降"，验证了三准则缺一不可。
- **59K 全量无增益**：在 59K 全量数据池上训练相比 1K 精选没有实质增益，呼应了 LIMA 等先前工作的发现。
- **顺序 vs 并行扩展**：对基座模型做 64 次采样、按 2/4/8/16/32/64 路多数投票，即使并行扩展也无法追上 s1-32B 的顺序扩展表现，验证了"顺序扩展优于并行扩展"。

## 结论与局限

**主要结论**：
1. 最简单的测试时缩放配方 = 1,000 个精心挑选的样本做 SFT + budget forcing 干预，即可获得强推理能力和测试时缩放行为。
2. 数据选择三原则（难度、多样性、质量）缺一不可；全量数据训练相比精选 1K 无实质增益。
3. 顺序（sequential）测试时缩放优于并行（parallel，如多数投票）缩放。

**局限**：
1. **Budget forcing 缩放会饱和**："过于频繁地抑制 end-of-thinking token 分隔符会导致模型陷入重复循环（repetitive loops）"，在 AIME24 上约 6 次 "Wait" 干预后曲线趋于平缓。
2. **与 DeepSeek r1 系列仍有差距**（AIME24 56.7 vs r1 的 79.8），1,000 样本能否达到同等水平是开放问题。
3. **选择偏差**：难度过滤所用的模型（Qwen2.5 系列）与微调模型相同，论文承认可能存在选择性偏差，但认为思路可推广。
4. **上下文窗口限制**会约束可扩展的思考长度上限。
5. **对比不完整**：Gemini API 的 "recitation error（背诵错误）" 使其 MATH500/GPQA 分数无法可靠评测（表中为 N.A.）。

**后续反调（rebuttal）**：
- **arXiv:2507.14419《It's Not That Simple. An Analysis of Simple Test-Time Scaling》（Guojun Wu）**：直接分析并批判 s1 方法，认为其观察到的"缩放"主要是"向下缩放（scaling down）"——通过强制最大生成长度截断产生的假象，而非真正通过更多计算换来的"向上缩放"；对蒸馏长 CoT 数据做 SFT 对缩放行为没有显著贡献；追加 "Wait" 强制延长推理会导致模型在不同解之间振荡而不收敛。真正的测试时缩放（如 DeepSeek-R1 这类经 RL 训练、天然随预算增长超越峰值表现的模型）应当能在更多计算下突破原模型峰值。
- **arXiv:2502.12118《Scaling Test-Time Compute Without Verification or RL is Suboptimal》（Amrith Setlur 等）**：从理论层面证明，在固定计算/数据预算下，无验证器（verifier）的测试时计算缩放（如 s1 这类蒸馏/克隆搜索轨迹的 VF 方法）是次优的；基于验证器（VB，用 0/1 奖励、奖励模型或验证器引导 RL 与搜索）的方法扩展性远优于前者，且随计算量与数据规模扩大，VF 方法的次优性会加剧。

## 与 harness × 模型训练的关系

s1 是"测试时缩放（test-time scaling）"路线的代表作：它不在训练侧下重注——只用 1,000 个样本、26 分钟 SFT，而是在推理/解码时对模型的思考过程做运行时干预（budget forcing），把"更多计算"直接转化为"更长、更深的思考"，从而在不大幅改动模型权重的情况下挤出推理收益。这与 harness 训练形成鲜明对比：harness 侧的收益来自对外部控制层（上下文组装、工具交互、编排、记忆、解码配置、输出处理）的运行时编排，同样不依赖大规模权重更新。对 harness 运行时干预的直接启示有三点：(1) 解码/生成控制（decoding/generation control）是 harness 诸维度中"性价比"极高的一维——仅仅控制思考 token 的上下限、或在关键时刻追加一条反思指令（如 "Wait"），就能产生数个百分点级的可外推收益；(2) s1 之后的反调（2507.14419、2502.12118）提醒：这类干预存在饱和点、且对某些模型（尤其 RFT/蒸馏类）可能适得其反，"更多思考"并不总是"更深思考"，harness 需要按任务与模型自适应地决定预算而非盲目拉长；(3) 测试时缩放与训练/微调并非互斥而是互补——s1 靠微调赋予模型"会自我纠错"的基础能力，再靠运行时干预放大该能力，这与 harness 用外壳放大基础模型能力是同一逻辑：模型侧负责"能力上限"，harness 侧负责"把能力用好"。
