# 感知 Harness 的自我进化：协同进化模型权重、Harness 与任务解法（HASE: Harness-Aware Self-Evolving / Harness-Aware Self-Evolving: Co-Evolving Model Weights, Harness, and Task Solutions）
- 作者 / 机构：Haochen Luo, Yi Huang, Sichun Luo, Fengyuan Liu, Lei Li, Zefa Hu, Junlan Feng, Qi Liu（香港大学 HKU、中国移动 China Mobile、格瑞投资机器 Grace Investment Machine）
- 出处：arXiv:2607.03935 [cs.AI]（v1，2026-07-04 提交）
- 原文链接：https://arxiv.org/abs/2607.03935

## 摘要（中文翻译）

自我进化框架通常只优化任务解法，而将模型周围的 harness（缆线/脚手架，指调节模型与任务交互的所有组件：提示词、记忆、上下文检索、工具接口、状态管理与评估器等）视为固定不变。我们提出 **HASE（Harness-Aware Self-Evolving，感知 Harness 的自我进化）**，一个 agentic 强化学习框架，其中**单个模型**即可在多轮（multi-turn）动作空间里生成任务解法，或编辑被选中的 harness 组件——无需一个独立的、能力更强的"编码提议者"（proposer）。在文本分类任务上，HASE 使单个 Qwen3-8B 模型追平了一个使用 Claude Code 作为 harness 提议者的 GPT-OSS-120B 模型所达到的性能。在 alpha factor mining（alpha 因子挖掘，量化选股因子搜索）中，HASE 超越了所报告的 GPT-OSS-120B 基线。此外，HASE 能够修复有缺陷的评估组件（evaluation components），并在圆形打包（circle-packing）算法发现任务上收敛到最优水平（state of the art）。这些结果表明，HASE 通过一个统一的 agentic 流程同时改进了 harness 与解法。

## 核心贡献
- **统一的 harness 感知自我进化框架**：将策略（policy）、任务解法与选中的 harness 组件置于同一个多轮动作空间内协同进化，由单一模型完成，"无需独立的能力更强的编码提议者"。模型在每一轮中自主决定是提交一个对象级（object-level）解法，还是使用沙箱（sandbox）工具检查并修改可编辑的 harness。
- **区分两类 harness 组件并采用不同进化规则**：评估组件（evaluation components，局部可编辑的验证器/评分器）只在局部代理评分（proxy score）与真实世界评估器的 oracle 评分（oracle score）出现分歧时才被修复；指导组件（guidance components，提示词、记忆格式、检索脚本、上下文选择）则通过 proof-of-concept（PoC，概念验证）奖励进行搜索空间改进，不改变任务正确性。
- **实证验证覆盖三个任务族**：文本分类（追平 GPT-OSS-120B + Claude Code 基线）、alpha 因子挖掘（超越 GPT-OSS-120B 基线）、几何算法发现（在"损坏的评估器"下修复评估器并达到最优水平）。
- **对"损坏评估器"下的算法发现的系统研究**：展示了 HASE 如何识别被解法利用的评估器缺陷、迭代修复，并让策略通过 RL 内化修复后的约束。

## 方法（中文翻译）

### 1. 两类 Harness（Harness 的类型学）

论文将 harness 定义为"调节模型与任务交互的组件，包括提示词、记忆、上下文检索、工具接口、状态管理与评估器"，并将其分为两类：

- **评估组件（Evaluation Components）**：系统允许编辑的局部评估器（验证器 validators、评分器 scorers），它们产生稠密训练信号，即**代理评分（proxy score）**，该评分可能不准确。与之相对的**真实世界评估器（real-world evaluator）** 不可编辑、位于系统外部，产生保证准确的 **oracle 评分（oracle score）**。论文的原则是："真实世界评估器是可编辑局部评估器进化的锚点"。当代理评分与 oracle 评分出现分歧时，被提交的解法会被加入一个**失配集合 ℳ（mismatch set）**，作为未来评估器修复的测试用例。
- **指导组件（Guidance Components）**：提示词、记忆格式化、检索脚本、上下文选择等。它们"在不改变任务正确性的前提下改进搜索"。

### 2. 统一动作空间

模型在每一轮可以：提交一个对象级解法，或者使用沙箱工具检查与修改可编辑的 harness。沙箱命令包括 `ls`、`cat`、`grep`、`replace`、`overwrite` 与 `done`。不存在硬编码的规划器来决定"该解题还是该编辑"，"由当前上下文决定哪种动作是有用的"。

### 3. HASE 算法（Agentic RL 框架）

- **持久化状态**：持久化 harness *h*、策略 *π_θ*、阶段局部候选池 *C_p*，以及（可选）失配集合 *M*。
- **多阶段训练**：每个阶段包含多个 GRPO（Group Relative Policy Optimization，群体相对策略优化）epoch；rollout 是多轮轨迹（multi-turn trajectories），可以检查/编辑文件，最终提交一个解法。
- **Rollout 局部与持久化更新分离**：rollout 局部的 harness 编辑只影响产生该编辑的轨迹；持久化 harness 只在阶段级评审（phase-level review）之后才更新。
- **奖励设计**："HASE 不会单独奖励 harness 相关的动作本身"。
  - 指导类编辑采用**PoC（概念验证）** 方式：该轨迹必须实际使用被编辑的 harness 并获得改进的任务奖励，奖励为 `R_PoC(τ) = max{0, R_task(τ;h′) − R_base(x,h)}`，即编辑后任务奖励相对基线奖励的正向增益。
  - 评估类编辑只在"代理评分与 oracle 评分不一致"时获得奖励，奖励与失配集一致性的提升成比例。
- **Harness 选择**：在阶段边界，指导候选按验证性能评审；评估补丁只有在"在修复 ℳ 中更多失配、同时保留所需评估器接口与不回归（non-regression）用例"时才被接受。提交采用最佳评审验证分数，而非单条轨迹的最高 PoC，从而避免对噪声轨迹过拟合。

### 4. 指导 Harness 进化

rollout 局部的指导编辑通过 PoC 分数存入 *C_p*："可解析且 PoC 分数为正的指导编辑存入阶段候选池"。在阶段边界，HASE 过滤无效或重复的编辑、遴选有潜力的候选，并在任务协议（protocol）下评估遴选出的 harness，按最佳评审验证分数提交。

### 5. 评估 Harness 进化

评估器编辑"被区别对待，因为它们定义了奖励本身"。真实世界反馈只在阶段边界查询一次，这"镜像了真实世界的调试场景：随着新的反例不断出现，问题被迭代地发现与修复"。对当前失配集的一致性"并不保证评估器在未来所有解法上都永远正确"。核心原则是："评估器修复不是无约束的奖励改写。每次编辑都由观测到的 oracle 分歧触发。"

## 实验结果

### 任务总览（表 1）

| 任务 | 可编辑 Harness | 类型 |
|---|---|---|
| Heilbronn 三角形 | 提示词 + 评估器 | Eval + Guidance |
| 圆形打包（Circle packing） | 提示词 + 评估器 | Eval + Guidance |
| 文本分类（Symptom2Disease） | 上下文 + 记忆 | Guidance |
| Alpha 因子挖掘 | 上下文 + 提示词 | Guidance |

### 评估 Harness 进化——圆形打包（Circle Packing）

- HASE 从不完整的评估器出发，达到最优打包分数 **2.635983**，与 AlphaEvolve 的最优水平（state of the art）持平。
- 记录了两次修复循环：初始验证器"省略了边界与重叠约束"。阶段 0–1 中解法利用了这一缺口，"代理评分 35.459643 而 oracle 返回 0"。第一次修复"加入边界与重叠检查"，使代理与 oracle 在 2.607072 处重新对齐。随后一个候选暴露了过松的重叠容差（10⁻⁸ 对比任务规定的 10⁻¹²）；最终修复将其收紧，此后"代理与 oracle 保持对齐"。

### 评估 Harness 进化——Heilbronn 三角形

- 任务：在单位等边三角形内放置 N=11 个点，最大化"任意三点所成三角形的最小面积"。
- 设置：Qwen3-8B，8× NVIDIA H20 节点，VeRL RL 框架，每阶段 32 个提示词、每提示 32 条轨迹（共 1,024 条），批大小 32，每阶段 1 个 PPO epoch。
- 初始弱评估器只检查 NaN/inf 与点数，"完全省略边界检查"。阶段 0 的利用：一个差分进化（differential evolution）求解器"将点放在边界之外很远"，得到"高代理评分 0.027076，而 oracle 评分为 0.0"。HASE 随后提交一个"重心坐标符号检查"来弥合这一缺口。
- **FREEZE 消融**：修复评估器但冻结权重时，最终有效分数停滞在 0.021880；**完整协同进化（FULL co-evolution）** 在第 8 阶段达到 **0.036082**。结论："RL 更新让策略内化修复后的约束并继续优化。"

### 指导 Harness 进化——文本分类（Symptom2Disease）

- **设置**：与 Meta-Harness 相同的划分——200 训练、50 验证、212 测试，22 个疾病类别。"训练集是唯一的检索池"。测试使用"单次尝试贪心 vLLM 推理"与冻结的已提交 harness——"无测试时编辑、微调、重试或对测试样本的检索"。
- **结果（表 2，准确率）**：

| Harness | 解码器 | 准确率 |
|---|---|---|
| Zero-shot | GPT-OSS-120B | 63.2 |
| Few-shot (8) | GPT-OSS-120B | 67.9 |
| MCE | GPT-OSS-120B | 83.0 |
| ACE | GPT-OSS-120B | 77.8 |
| Meta-Harness | GPT-OSS-120B | 86.8 |
| Five-shot | Qwen3-8B | 59.4 |
| **HASE harness** | **Qwen3-8B** | **86.98 ± 0.38**（5 个随机种子） |

- 单独的 8B few-shot 基线较弱，"但被发现的 HASE harness 把同一个 8B 模型带到了 Meta-Harness 的操作点"——即 **Qwen3-8B + HASE harness 打平了 GPT-OSS-120B + Claude Code harness 提议者的基线**。
- **工具进化的定性模式**（附录 A.1）：两类反复出现的模式——关键词定位的重叠打分（如发烧/肌肉疼痛查询最初被误判为肺炎，随后 agent 用症状重叠打分覆盖 `classification_tools.py`，检索登革热/伤寒样本并自我纠正为登革热）与基于相似度的检索注入（脱皮/关节痛案例从真菌感染纠正为银屑病）。
- **训练时行为（表 4）**：第 0 阶段之后，模型稳定地进行工具编辑（每 epoch 约 2.3–2.4 次）、多轮交互（约 3.5 轮/epoch）与读操作（约 1.2 次/epoch）。

### 指导 Harness 进化——Alpha 因子挖掘

- **设置**：CSI300 基准，10 日前向收益目标，按时间划分——训练 2011–2019、验证 2020、测试 2021–2024。"harness 搜索与阶段边界评审只使用训练与验证期"。可编辑表面限制为 `prompt.txt` 与 `pool_viewer.py`；"金融评估器全程固定"。
- **Harness 进化轨迹（图 4）**：从仅近期（recency-only）上下文 → 完整因子池访问 → 在上下文预算下按 IC 排序的检索。早期提示词加入"IC 目标与动量/波动率先验"；最终提示词注入"最优 IC、因子池范围、AER 与混合搜索先验"。

- HASE"在组合盈利性上超越 GPT-OSS-120B（AER 14.35% 对比 7.89%，IR 1.70 对比 0.80），同时预测相关性与之接近（RankIC 0.0302 对比 0.0318）"。注意 HASE 使用的是固定的金融评估器——所有增益都来自指导类 harness（提示词与因子池查看器）的进化。
- **评估控制（附录 B）**：
  - **Universe 构造**：作者指出 CSI300 名单常把指数代码也列为可交易标的；他们使用 CogAlpha 整理的 `qlib_CSI300.csv`，含 754 只纯成分股。
  - **泄漏检测**：因果不变性检测器——若某个因子读取未来行，当未来数据被扰动时"其在所有到 T 为止的行上必须产生相同输出"；外加针对数组长度依赖（如负索引回绕 bug）的截断检查。
  - **跨 LLM 审计**："四个独立 LLM 法官对 30 个因子给出 120/120 的一致 CLEAN 判定"（Gemini、ChatGPT、DeepSeek、Claude Sonnet）。
  - **模拟**：Qlib 模拟器，含"交易成本、最低成本约束与 9.5% 涨跌停约束（open_cost=0.0005、close_cost=0.0015、min_cost=5）"。

## 结论与局限

**结论**：HASE"让单个模型既能改进任务解法，也能改进其自身 harness 中被选中的组件"，包含两种进化形态——指导组件"提升解法搜索质量"，而评估组件"只在局部评估器的代理评分偏离真实世界评估器的 oracle 评分时才被修复"，这既"识别出评估器缺陷"，又避免了"无约束的奖励黑客（reward hacking）"。结果总结：文本分类追平 GPT-OSS-120B + Claude Code；alpha 因子挖掘超越 GPT-OSS-120B；几何算法发现在损坏评估器下修复评估器并达到最优水平。框架被描述为"在单一统一 agentic 系统中协同进化模型策略、harness 与任务解法的实用框架"。

**局限**：
- "我们的实验在四个任务设置上建立了 harness 感知的自我进化，但它们不是一项穷尽的规模缩放（scaling）研究。"——未做全面的规模/扩展性研究。
- 保守的工程选择"以通用性换取安全性"：可编辑组件采用白名单；评估器编辑要求代理–oracle 分歧；阶段边界评审只提交接口合法的补丁。这些"可能拒绝有用但更具侵入性的修改"。
- 未来工作可"扩展可编辑表面、增加更强的静态与动态测试、使用信息更丰富的失配集，同时保留同一安全原则：指导类编辑与定义正确性的评估类编辑必须区别治理"。

## 与 harness × 模型训练的关系

HASE 把"harness 进化"与"模型训练"放进同一个 agentic 循环，是 harness 项目（EZAgent/HiAgent）所关心的"harness 设计如何决定 agent 行为"的直接延伸，但其关键创新在于把 harness 本身也变成了被优化对象，且由同一模型、通过同一 RL 过程来优化。它与 Meta-Harness（用 Claude Code 作为外层提议者改写另一个模型的 harness）形成对照：Meta-Harness 需要能力更强的外部提议者、且只处理指导组件；HASE 则把 harness 编辑与任务解题放入单一统一动作空间，消除了对外部强提议者的依赖——这也是文本分类任务上 Qwen3-8B 能打平 GPT-OSS-120B + Claude Code 基线的核心原因。同时，HASE 对评估组件的"代理–oracle 分歧驱动修复"机制，为 harness 项目中"评估器与验证器也是需要被维护、被对齐的活体组件"提供了具体算法：每当内部代理评分与外部真值评分背离，就把失配样本存入失配集、触发评估器修复，从而在不开启无约束奖励改写的前提下防范 reward hacking。总体而言，HASE 为"harness 与模型训练协同"提供了一条单模型即可落地、且刻意保守于安全性的实践路径，对任何以 harness 为核心、希望在自进化循环中同时改善搜索脚手架与策略权重的项目都具有直接参考价值。
