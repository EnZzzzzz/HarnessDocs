# 智能体从轨迹 SFT 中学到了什么：语义还是接口？（What Do Agents Learn from Trajectory-SFT: Semantics or Interfaces?）
- 作者 / 机构：Weizheng Gu, Chengze Li, Zhuohao Yu, Mengyuan Sun, Zhibang Yang, Wei Wang, Hongrui Jia, Shikun Zhang, Wei Ye（arXiv 摘要页未列出具体机构，仅提供了提交作者 Weizheng Gu 的联系邮箱）
- 出处：arXiv:2602.01611
- 原文链接：https://arxiv.org/abs/2602.01611

## 摘要（中文翻译）

大语言模型正越来越多地被作为交互式智能体（interactive agent）来评估，然而标准的智能体基准（benchmark）混淆了两种性质截然不同的成功来源：语义化的工具使用（semantic tool-use）与针对特定接口的交互模式记忆（interface-specific interaction pattern memorization）。由于这两种机制在原始接口上都可能带来完全相同的任务成功表现，因此仅凭基准分数并不能作为环境无关能力（environment-invariant capability）的可识别证据。我们提出 PIPE——一种协议级（protocol-level）的评估增强方法，通过最小化地改写环境接口、同时保留任务语义与执行行为，来诊断接口依赖（interface reliance）。在对来自 AgentBench 与 AgentGym 的 16 个环境以及一系列开源与基于 API 的智能体的实验中，PIPE 揭示了轨迹 SFT（trajectory-SFT）会显著放大接口捷径效应（interface shortcutting）：经过训练的智能体在最小的接口改写下急剧退化，而未经轨迹训练的模型则大体保持稳定。我们进一步提出 Interface Reliance (IR)——一种基于消偏（counterbalanced）别名（alias）的指标，用于量化对训练期接口的偏好，并表明接口捷径效应表现出随环境变化、非单调（non-monotonic）的训练动力学，而这一现象在标准评估下是完全不可见的。我们的代码已公开发布。

## 核心贡献
- 揭示了轨迹训练智能体评估中存在的一个根本性歧义：成功率提升无法区分「真正的语义学习」与「接口捷径（interface shortcutting，即复现训练期接口的表层交互形式）」。
- 提出 PIPE——一个协议级诊断框架，在保留任务语义的前提下对环境接口做最小扰动，并在现有基准上引入 IR 指标以隔离并量化接口捷径。
- 通过大规模评估证明轨迹 SFT 内在地会诱发接口捷径，且其严重程度随环境复杂度而变化，验证了细粒度诊断的必要性。
- 关键警示：benchmark 分数不能作为区分「真实语义学习」与「接口模式记忆」的可识别证据——这正是本论文对 harness（评测框架）× 模型训练关系的最核心提醒。

## 方法（中文翻译）

**形式化的智能体评估协议。** 论文将环境 ℰ 形式化为三个组成部分：一段环境描述提示词（description prompt）P_ℰ、一个动作集合（action set）𝒜^ℰ，以及一份接口规范（interface specification）ℐ^ℰ = {D_i}，其中每个 D_i 都包含动作名称、功能性描述（functional description）与调用格式（invocation format）。智能体策略 π_θ 每一轮以文本形式产生动作调用；环境解析合法调用、执行之并返回观测。轨迹 SFT 数据集正是通过同一套协议、由强教师模型（teacher）采集得到的，因此微调后的智能体在训练与评估阶段面对的是同一份接口——这为接口层面的捷径利用留出了空间。

**PIPE：最小接口扰动。** PIPE 通过仅改写接口规范 ℐ^ℰ 来构造扰动后的对照环境 ℰ′，而保持可执行行为、任务与观测完全不变。它定义了两种扰动家族：
- 同义词扰动（Synonym-based perturbation）：用语义相近的替代名称替换动作名，保留其自然语言含义。
- 符号扰动（Symbol-based perturbation）：用无语义含义的符号令牌（token）替换动作名，同时保留详细的动作功能描述。

由于每个函数仍保留详细的功能描述，任务的内在难度得以保持，从而隔离出对表层形式的依赖。诊断信号为性能差距 Δ(π_θ; ℰ) = Score(π_θ; ℰ) − Score(π_θ; ℰ′)：Δ 大说明对原始接口表层形式的依赖更强，Δ 小则提示语义依赖。

**Interface Reliance (IR) 指标。** IR 用于度量智能体对两个功能完全等价的别名（原始名 vs. 同义词名）同时出现时的偏好程度：

IR(ℰ) = exp( (1/K) Σ_{k=1}^{K} log( (n_ori^(k) + α) / (n_syn^(k) + α) ) )

即各任务偏好比率的几何平均，α > 0 为伪计数（pseudo-count）平滑项。评估采用消偏协议：分别以「原始名在前」与「同义词名在前」两种提示词顺序各跑一遍，对每个任务的调用次数取平均后再计算 IR。采用几何平均形式（附录 G 论证）是因为朴素地对比率做算术平均会被极端任务主导——例如当 α=1 时，任务 (0,1) 与 (20,0) 会得到 10.75 的朴素均值，几乎完全由退化任务驱动；而对数空间聚合能以均衡、乘性的方式对待每个任务在接口上的投入程度。

## 实验结果

**重评设置与难度校验。** 将 PIPE 应用于 AgentBench（→ AgentBenchPlus）与 AgentGym（→ AgentGymPlus），覆盖 16 个环境。评估的模型包括 GPT-3.5、GPT-4o-mini、GPT-5-mini；AgentLM-7B/14B/70B 与 AgentFLAN（在 AgentBench 上做轨迹 SFT）；以及作者在 AgentGym 的 AgentTraj 数据上自行微调的 Qwen3-8B/14B 与 Gemma3-4B/12B。Δ 定义为两种扰动条件下的 (s1 + s2)/2 − s0。

**PIPE 并非统一地增加任务难度。** 未训练的智能体 Δ 值较小或正负混合，有时甚至表现更好（如 AgentBenchPlus 上的 KnowledgeGraph 与 Mind2Web）；在 AgentGymPlus 上，未训练智能体的 Δ 平均接近零。

**轨迹 SFT 智能体不成比例地脆弱（核心发现）。** 在接口扰动下轨迹 SFT 智能体表现出不成比例的脆弱性：
- AgentBenchPlus：AgentLM-14b 在 WebShop 上从 61.2（原始接口）骤降至 4.44/3.08（扰动接口）；AgentLM-70b 在 DataBase 上从 42 跌至 2/13.3。AgentFLAN 受影响通常较小，与其「将格式遵循与推理解耦」的目标一致——不过作者指出「这是相关性的观察，而非因果归因」。
- AgentGymPlus：训练后的智能体在 WebShop 原始接口上可达 80–90+，但收益「仅部分迁移」——在 ALFWorld、SciWorld 与 WebShop 上出现显著下降，不过训练后的智能体通常仍高于未训练基线。这种「部分迁移」模式支持双效应论断：轨迹 SFT 既提升了语义能力，也诱发了接口捷径。
- 稳健子集：SQLGym 与 TextCraft 的差距较小；附录将其归因于动作空间有限、任务结构的强语义锚定，以及可用于捷径利用的空间减少。

**失败分析：遗留动作调用（legacy action invocations）。** 案例研究表明，训练后的智能体即使在明确的纠正性反馈下，仍会持续输出已废弃的训练期动作名——例如在 WebShop 中，click 被重命名为 press 后，智能体「尽管环境已明确限制有效动作，仍反复输出 click[…]」；在 ALFWorld 中，导航动作被重命名为 navigate to <object> 后，智能体仍继续输出 go to <object>。量化上（图 3 与附录表 9），「未训练的智能体几乎从不产生此类无效调用」，而训练后的智能体在 SciWorld、ALFWorld 与 BIRD/SQLGym 中频繁产生遗留调用。

**IR 结果。** IR 呈现分裂模式：
- 训练后出现高 IR（强接口依赖）：AgentBenchPlus 的 ALFWorld（AgentLM-13b 约 15.50，AgentLM-70b 约 9.91）、DataBase 与 OperatingSystem；AgentGymPlus 的 SciWorld（Gemma3-4b 最高达 7.69）与 ALFWorld。
- IR ≈ 1（弱偏好）：KnowledgeGraph、WebShop（AgentBenchPlus）、Wordle、MAZE（AgentGymPlus），这些环境没有任何一个别名家族占主导。

作者据此得出结论：轨迹 SFT 所诱导的接口依赖程度高度依赖于环境。

**训练期动力学（案例研究）。** 在 AgentInstruct 上对 Qwen3-8B 微调 8 个 epoch，并对 DataBase 与 OperatingSystem 上的各检查点（checkpoint）进行评估，结果表明「Origin 上的训练进展并不能可靠地指示语义学习」。在 DataBase 上，早期训练提高了 Origin 分数，却同时降低了扰动接口的表现并推高了 IR；继续训练则部分恢复扰动接口表现、IR 略有下降。在 OperatingSystem 上恢复则更弱。因此，仅依据 Origin 分数来选择检查点，「可能会让人偏好一个在最小接口改写下更脆弱的模型」。

## 结论与局限

**结论。** 轨迹微调确实能大幅提升 benchmark 分数，但「轨迹 SFT 收益中相当一部分对接口变化是脆弱的」。PIPE 被作为一种简单、保持语义的评估期协议提出，用以把语义能力与接口捷径解耦，从而推动智能体评估中的接口感知诊断。

**局限 / 注意事项（论文原述）：**
- 论文没有专门的局限章节；其 Impact Statement 写道：「我们的工作存在许多潜在的社会影响，但其中没有哪一项我们认为需要在此特别强调。」
- 若干需要在线 API 调用的 AgentGym 环境因网络限制被排除，因此结果未必能泛化到依赖 Web 的场景。
- 关于 AgentFLAN 的观察是相关性的，而非因果性的。
- 接口扰动「在工具种类更丰富、更多样的环境中最为有效」；低工具多样性环境可能本质上就压制了捷径的产生，从而降低诊断的区分度。
- Mind2Web 被排除在 IR 分析之外，因为它缺少显式的动作列表，无法自然地构造双别名。
- 附录 D 提出了一条设计原则：当训练制度「宽松」（函数少、监督充足）时，智能体更可能学到工具语义；当制度「高压」（函数多、数据有限）时，更可能学到接口捷径——例如，把复杂的多工具轨迹分解为更简单、聚焦于单一工具的子轨迹，可能使训练更偏向语义学习。

## 与 harness × 模型训练的关系

这篇论文是对「benchmark 分数不能区分真实语义学习与接口模式记忆」这一问题的直接警示。它说明：当评测协议与训练接口高度一致时，标准 benchmark 上的分数提升既可能来自环境无关的语义能力，也可能只是模型记住了训练期接口的表层交互形式（如动作名与调用格式）。PIPE 通过在保留任务语义与执行行为的前提下最小化改写接口（同义词扰动与符号扰动），把「性能差 Δ」作为接口依赖的诊断信号，并辅以 IR 指标量化对训练期接口的偏好。这带来的启示是：任何把 benchmark 分数当作模型「真实学会工具语义」证据的做法都是不充分甚至误导性的；在为 harness（评测框架）与模型训练做设计时，应引入接口层面的诊断（例如在保持语义的前提下改变接口表层形式），以区分真实语义泛化与接口模式记忆。对模型训练而言，训练制度（函数数量、数据充分性、监督粒度）会显著影响模型偏向语义学习还是接口捷径，因此评估与调参都应当在接口扰动这一维度上做敏感性检验。
