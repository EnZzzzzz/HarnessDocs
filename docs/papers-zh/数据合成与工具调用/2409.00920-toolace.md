# ToolACE：在 LLM 函数调用（Function Calling）中赢下关键分（ToolACE: Winning the Points of LLM Function Calling）

- 作者 / 机构：Weiwen Liu, Xu Huang, Xingshan Zeng, Xinlong Hao, Shuai Yu, Dexun Li, Shuai Wang, Weinan Gan, Zhengying Liu, Yuanqing Yu, Zezhong Wang, Yuxian Wang, Wu Ning, Yutai Hou, Bin Wang, Chuhan Wu, Xinzhi Wang, Yong Liu, Yasheng Wang, Duyu Tang, Dandan Tu, Lifeng Shang, Xin Jiang, Ruiming Tang, Defu Lian, Qun Liu, Enhong Chen（共 27 位作者）。arXiv 与 ICLR 官方页面未明确列出机构；该团队以 Team-ACE 名义公开发布模型与数据，公开信息显示其与华为诺亚方舟实验室（Huawei Noah's Ark Lab）及合作机构相关。
- 出处：arXiv:2409.00920 · ICLR 2025
- 原文链接：https://arxiv.org/abs/2409.00920

## 摘要（中文翻译）

函数调用（function calling）显著扩展了大语言模型（LLM）的应用边界，而高质量、多样化的训练数据是解锁这一能力的关键。然而，真实的函数调用数据极难采集与标注；现有流水线（pipeline）生成的合成数据又往往缺乏覆盖度与准确性。本文提出 ToolACE——一个自动化的智能体流水线（agentic pipeline），用于生成准确、复杂且多样化的工具学习（tool-learning）数据。ToolACE 利用一种新颖的自我演化合成（self-evolution synthesis）流程，精心构建了一个包含 26,507 个多样化 API 的综合 API 池。对话则通过多个智能体（agent）之间的交互生成，并由一种形式化的思考过程（formalized thinking process）加以引导。为确保数据准确性，我们实现了一个结合基于规则（rule-based）与基于模型（model-based）检查的双层验证系统。我们证明：使用所合成数据训练的模型——即便参数规模仅有 8B——也能在伯克利函数调用排行榜（Berkeley Function-Calling Leaderboard, BFCL）上取得最先进的性能，与最新的 GPT-4 模型相媲美。我们的模型及部分数据已公开，可从 https://huggingface.co/Team-ACE 获取。

> 说明：以上为 arXiv v1（2024-09-02）摘要的忠实翻译。ICLR 2025 正式版（camera-ready）摘要措辞略有差异，其中将引导对话生成的过程表述为"一个复杂性评估器（complexity evaluator）"，与 arXiv 版的"形式化思考过程"对应。

## 核心贡献

- **提出 ToolACE**：一个端到端自动化的数据生成智能体流水线，用于产出准确、复杂且多样的函数调用训练数据，覆盖真实世界 API 交互中"多样、复杂、相互依赖"的特点。
- **工具自我演化合成（Tool Self-Evolution Synthesis, TSS）**：通过分域（Speciation）、适配（Adaption）、演化（Evolution）三步，自动合成并筛选出一个覆盖 30 个主域、390 个子域、3,398 个细粒度域、约十万项具体功能、共 **26,507 个多样 API** 的 API 池，远超此前数据集。
- **多智能体交互式对话生成（Multi-Agent Interactive Dialogue Generation, MAI）**：由 LLM 扮演用户、助手、工具（执行器）三个智能体交互生成对话，并引入形式化思考过程与自一致性（self-consistency）机制保障对话质量。
- **双层验证系统（Dual-Layer Verification, DLV）**：基于规则层 + 基于模型层双重校验，确保数据准确性与可执行性，显著抑制幻觉。
- **数据三大支柱**：多样性（Diversity，工具/格式/对话三个维度）、复杂性（Complexity，依据最近发展区 ZPD 理论将数据难度校准到略高于模型当前水平）、准确性（Accuracy，形式化思考 + 自一致性 + 双层验证）。
- **实验成果**：基于 LLaMA3.1-8B-Instruct 微调得到的 **ToolACE-8B 在 BFCL-v1 与 BFCL-v2 上均排名第一**，总体准确率分别达 91.41% 与 85.77%，超越多个最新的 GPT-4 系列模型与同规模开源模型，展示了小模型 + 高质量合成数据的组合威力。

## 方法（中文翻译）

ToolACE 的数据生成流水线由三个核心模块组成。

### 1. 工具自我演化合成（TSS）：构建多样化的 API 池

TSS 用于合成包含多样数据类型与约束的 API 定义，分为三步：

- **分域（Speciation）**：从预训练语料（手册、API 文档、指南等）中抽取并构建一棵"分层的 API 上下文树"（hierarchical API context tree）。该树覆盖 30 个主域、390 个子域、3,398 个细粒度域，以及估计约十万项具体功能。
- **适配（Adaption）**：在细粒度层面采样子树作为 API 的上下文；越复杂的 API 覆盖越多的节点。
- **演化（Evolution）**：由 LLM 基于采样得到的子树、并结合"API 示例缓冲池"（API example buffer）中的一个示例，合成新的 API；多样性信号包括"增加新功能或参数、加入额外约束、改变参数类型、更新返回结果"等。该过程最终产出 26,507 个各不相同的 API。

> 与既有数据集对比（数据规模/覆盖域）：Gorilla 1,645 个 API / 3 个域；ToolAlpaca 3,938 / 50；ToolLLM 16,464 / 49；xLAM 3,673 / 21；**ToolACE 26,507 / 390**。ToolACE 同时支持嵌套参数、并行调用、依赖调用与多类型数据，而此前数据集往往只覆盖其中部分子集。

### 2. 多智能体交互式对话生成（MAI）：生成多样化的对话

（注：论文中该模块名为 MAI，即 Multi-Agent Interactive Dialogue Generation。请求模板中称其为"SDG 自引导对话生成"，并非论文原文所用名称，特此说明。）

该模块让三个由 LLM 模拟的智能体交互：**用户（user）**、**助手（assistant）**与**工具（tool，即执行器 executor）**。其关键策略包括：

- **多模式提示（Multi-Mode Prompting）**：生成单轮/多轮、单次/并行/依赖调用，以及不使用工具（无合适工具、或信息不足）的对话。
- **相似度引导的复杂化（Similarity-Guided Complication）**：使用多种语言风格的模板，并在事后通过相似度指标计算对话的复杂性。
- **形式化思考（Formalized Thinking）**：结构化的思考过程——"1) 评估用户查询，2) 评估工具需求，3) 确保所有必要参数均已提供"。该过程仅在生成阶段使用，不进入训练数据。
- **自一致性（Self-Consistency）**：每条助手回复生成 N 次，仅当其中至少两份实例的动作决策一致时（多数投票）才采纳；否则丢弃该轮或将损失（loss）遮蔽。
- **工具格式泛化（Tool Format Generalization）**：对话先以 JSON 存储，再转换为 JSON、YAML、XML、Markdown 等多种格式，以提升格式合规性。

### 3. 双层验证系统（DLV）：保证数据准确性

- **规则验证层（Rule Verification Layer）**：检查四个方面——"API 定义清晰度、函数调用可执行性、对话正确性、数据样本一致性"。其中可执行性无需真实执行即可验证：确认 API 名称存在于工具列表中、必要参数均已给出，并通过正则匹配校验格式/模式。
- **模型验证层（Model Verification Layer）**：将质量检查拆解为若干子查询，分别由专门的专家 LLM 智能体处理——"幻觉检测"（Hallucination Detection，针对编造的参数值）、"一致性校验"（Consistency Validation）、"工具响应检查"（Tool Response Check）。

## 实验结果

**实验设置**：以 LLaMA3.1-8B-Instruct 为基座，采用监督微调（SFT）方式 + LoRA 微调（rank 16、alpha 32、学习率 1e-4、warmup 比例 0.1、余弦学习率调度、batch size 48、3 个 epoch），所得模型命名为 ToolACE-8B。评估在 **BFCL-v1 与 BFCL-v2** 上进行。

**BFCL-v1 结果（排名第一）**：ToolACE-8B 总体准确率 **91.41%**，领先 Claude-3.5-Sonnet-0620（90.53）、Functionary-Medium-v3.1（88.88）、xLAM-7b-fc-r（88.76）、GPT-4-1106-Preview（88.53）与 Gorilla-OpenFunctions-v2（85.41）等模型。分类别成绩：AST 类别 **89.09**（Simple 95.50、Multiple 92.50、Parallel 90.50、Parallel-Multiple 98.24），Exec 类别 **94.00**（Simple 90.00、Multiple 85.00），相关性 Relevance **89.17**。论文指出 ToolACE-8B 在 BFCL-v1 的 AST 与 Exec 两个类别上均超越所有 API 模型与开源模型。

**BFCL-v2 结果（排名第一）**：ToolACE-8B 总体准确率 **85.77%**，领先 GPT-4-1106-Preview（85.65）、GPT-4o-mini（84.35）与 GPT-4-0613（84.23）等。分类别成绩：AST 类别 **71.03**（Simple 85.78、Multiple 87.13、Parallel 80.17、Parallel-Multiple 96.86），Exec **94.00**，Relevance **87.80**；在无关性检测（Irrelevance）上得分 81.44。在相关性指标上 ToolACE-8B 以 89.17% 超越全部对比模型。

**消融实验**：

- **形式化思考（Formalized Thinking）**：启用 FT 时最终通过率 61.8%，关闭时 49.8%，"最终通过率显著提升 10 个百分点（绝对提升）"。
- **验证系统**：双层验证的数据优于仅规则验证、也优于未经模型检查的数据（BFCL 上 AST 与总体准确率更高）；模型检查器"不可或缺"。
- **复杂性**：中等复杂性数据训练效果最佳，"过简或过复杂的数据都会损害性能"。
- **多样性**：API 多样性越高，准确率越高，在相关性/无关性检测上的提升尤为明显。

**规模扩展与泛化**：Qwen1.5 系列（0.5B/1.8B/4B/7B）微调后在各评估指标上"呈现一致的规模扩展行为"；在不同基座（Qwen1.5-7B、LLaMA-3-8B、LLaMA-3.1-8B）上微调均带来显著增益。在通用基准上，ToolACE-8B 相较 xLAM-7B-fc-r 在 MMLU、GSM8K、CommonSenseQA 上均更优，且相对于原始基座模型在通用基准上"性能退化可忽略不计"。

> 数据准确性说明：本论文的评测基准为 BFCL-v1 与 BFCL-v2，**未在 APIBank 上评估**；论文亦未报告多轮（multi-turn）对话工具调用的具体准确率数字（其表内 "Multiple/Parallel-Multiple" 列指单轮内多次函数调用，而非多轮对话）。请求模板中提到的"APIBank 评测"与"多轮工具调用准确率约 9.25%"并非出自本论文——经核查，"9.25%"出自后续论文 ToolACE-MT（ICLR 2026）：它指基座模型 LLaMA3.1-8B-Instruct 在 BFCL-v3 多轮（Multi-Turn）总体准确率上的基线得分，经 ToolACE-MT 训练后提升至 40.25%。为避免误导，此处予以如实标注。

## 结论与局限

**结论**：ToolACE 是一个旨在增强大语言模型函数调用能力的自动化数据生成流水线。论文表明，"即使是用 ToolACE 训练出的更小规模的模型，也能取得最先进的性能"，从而推动该领域发展，并为"工具增强型 AI 智能体（tool-augmented AI agents）"树立了新的基准。其成功依赖于多样性、复杂性与准确性三个支柱的协同，并验证了"数据即能力"这一思路对函数调用场景的有效性。

**局限**：原论文未设显式的"Limitations"小节。综合内容可归纳以下几点：1) 论文只评估了单轮内的多调用场景（BFCL 的 multiple/parallel 类别），未报告多轮（multi-turn）对话工具调用的定量结果，而论文本身也指出"诸如并行函数调用与多轮对话通常需要更多训练数据"；2) 训练数据规模（总对话样本数）在文中未明确给出，仅给出 API 数量与消融所用子集规模（复杂性消融约 6 万条、多样性消融约 3 万条实例）；3) 数据合成依赖 LLM 生成与模型验证，其成本与对更强教师模型的依赖未做系统讨论。如请求模板所述的多轮工具调用准确率"约 9.25%"并非本文数据（见上注），真实来源为后续工作 ToolACE-MT 对基座模型基线的测量。

## 与 harness × 模型训练的关系

ToolACE 属于"模型训练侧"的典型工作：它通过数据合成 + SFT/LoRA，把"发出合规工具调用（function calling）"这一技能注入基础模型，使其在给定 API 集合时能输出格式正确、参数完整、支持并行与依赖调用的函数调用——这正是智能体 harness（agent harness，运行框架/编排层）在运行时所需的前提输入。两者互补而非竞争：harness 负责在智能体循环（agent loop）中编排工具选择、执行与结果回填，前提是底层模型能稳定产出符合工具 schema 的调用；ToolACE 提供的高质量合成数据可用于训练这类"工具感知"模型，而 ToolACE 多智能体交互式生成对话的范式（用户/助手/工具三方角色）也与 harness 中的工具调用对话结构直接对应。若把 harness 视作"运行框架"、把函数调用能力视作"模型训练产出"，ToolACE 即为后者提供了数据侧的自动化工序，是构建可靠工具型 agent（如 Claude Code 类 harness 应用）中"让模型会调用工具"这一能力的有效训练方案。
