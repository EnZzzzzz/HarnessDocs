# MemoHarness：从经验中学习的智能体外壳（MemoHarness: Agent Harnesses That Learn from Experience）
- 作者 / 机构：Yue Huang, Wenjie Wang, Han Bao, Yuchen Ma, Xiaonan Luo, Yi Nian, Haomin Zhuang, Zheyuan Liu, Yue Zhao, Xiangliang Zhang（arXiv 页面未列出各作者的所属机构）
- 出处：arXiv:2607.14159
- 原文链接：https://arxiv.org/abs/2607.14159

## 摘要（中文翻译）

智能体外壳（agent harness）是外部控制层，它通过管理上下文（context）、工具（tool）、编排（orchestration）、记忆（memory）、解码（decoding）与输出处理（output handling），把基础 LLM（base LLM）转变为一个可执行的智能体（agent）。虽然外壳设计强烈影响智能体行为，但大多数自动改进方法只优化更狭窄的产物，例如提示词（prompt）、流水线（pipeline）或工作流（workflow），而已部署的智能体通常对所有案例复用同一个全局外壳。我们提出 MemoHarness，一个从自身执行中学习的自适应外壳优化框架。MemoHarness 将外壳分解为六个可编辑的控制维度，在双层经验库（dual-layer experience bank）中存储逐案例诊断（per-case diagnosis）与提炼出的全局模式（global pattern），并利用检索到的经验把学习到的外壳适配到每个测试案例，无需测试时标签（test-time label）、反馈或额外搜索。在我们对 shell 智能体（shell-agent）、代码生成与分析推理基准的评估中，MemoHarness 优于我们所比较的固定外壳，并对未见过的测试套件与基础模型表现出选择性迁移（selective transfer）。当大部分检索到的经验可缓存（cacheable）时，其额外上下文也能保持成本竞争力。这些结果提供了证据，表明执行经验是构建比单一静态配置更具自适应性智能体外壳的实用基础，同时把关于统计稳健性与组件归因的更广泛主张留待未来工作。

## 核心贡献

- **提出 MemoHarness**：一个从自身执行经验中学习的自适应 harness 优化框架。其核心主张是：同一基础模型、同一工具集下，仅靠外壳设计本身就能让端到端任务成功率摆动"几十个百分点"，但对外壳本身的自动化优化此前极为罕见——大多数方法优化的只是提示词、流水线或工作流等更狭窄的产物。
- **六维外壳空间（six-dimensional harness space）**：沿推理的时间流程把外壳分解为六个可编辑控制面，把搜索从"编辑单个不透明提示词"转变为"对可分离维度的结构化编辑"。
- **双层经验库（dual-layer experience bank）**：同时累积逐案例执行条目与提炼出的全局模式，使每一轮迭代都"诊断式（diagnostic）"而非"仅由分数驱动（score-driven）"。
- **测试时案例适配（test-time case adaptation）**：通过检索把学习到的全局外壳逐案例适配到每个测试用例，"无需任何测试时反馈、梯度更新或额外搜索轮次"。
- **结果与迁移**：在 Terminal-Bench 上达到 0.806（最强固定外壳基线为 0.722）；跨基础模型迁移使留出基础模型的平均任务成功率提升 +0.098，且额外上下文的成本在经验可缓存时仍具竞争力。

## 方法（中文翻译）

**问题形式化（§2.1–2.2）**：搜索案例（search case）有标签，评估案例（evaluation case）无标签——测试时适配只能使用可见特征与经验库，不能使用反馈。外壳是乘积空间 𝒲 = ∏ 𝒲⁽ᵈ⁾ 上的一个元组；轨迹记录预测结果、模型-工具轨迹与运行时诊断（调用次数、token 用量、延迟）。**总 token 用量是次级成本**（secondary cost）；美元成本在离线状态下按公开价目表（list price）计算。

**六维外壳空间（§2.3）**，六个可编辑控制面覆盖推理的完整时间流程：

| 维度 | 阶段 | 定义 |
|------|------|------|
| D1 | 上下文组装（context assembly） | 调用前的输入构建（提示词结构、示例、上下文压缩） |
| D2 | 工具交互（tool interaction） | 外部工具与检索的使用（是否启用检索、top-k、重排序） |
| D3 | 生成控制（generation control） | 解码配置（max tokens、temperature、采样） |
| D4 | 编排（orchestration） | 工作流拓扑（单次调用 → 规划/执行/修正） |
| D5 | 记忆管理（memory management） | 跨调用状态持久化（保留状态、摘要、丢弃过期状态） |
| D6 | 输出处理（output processing） | 调用后的输出处理（抽取答案、校验 schema、回退） |

**双层经验库（§2.4）**：经验库是一个带类型的二元组 ℬₜ = (ℰₜ, 𝒢ₜ)——(a) **逐案例执行条目** ℰₜ：每条包含配置增量（config delta）、奖励（reward）、成本（cost）与一条诊断 z（含成功标志、主要失败维度、次要维度以及自然语言分析）；(b) **全局模式** 𝒢ₜ：每 N 轮迭代由提炼器（distiller）从失败簇（failure cluster）中抽取"跨案例的持久规律（persistent cross-case regularities）"。控制器只检索有界切片（bounded slice），而非读取整个经验库。

**训练时优化（§2.5）**：从**最小外壳（minimal harness）W₀** 出发——无示例（demo）、无工具、确定性单次调用解码、无记忆、原始输出——使每个组件都必须由证据证明其必要性。选择采用**正确性优先的字典序排序（correctness-first lexicographic ordering）**：W⋆ ∈ argmax_lex (r̄ₜ, −c̄ₜ)——先最大化主奖励 r̄ₜ，仅当奖励相同时才以更低的 token 用量 c̄ₜ 作为决胜项。

**测试时适配（§2.6）**：对每个测试用例，按指令表征（instruction representation）的余弦相似度检索 top-K 相似的成功与失败历史条目，加上特征条件切片与全局模式，然后输出一个案例专属外壳 W(x) = Π_test(W⋆, x, S_test(x))——**无反馈回路、无重新选择**。

## 实验结果

- **RQ1 — 绝对提升（Terminal-Bench）**：MemoHarness 达到 **0.806**，超过 Codex（0.722，+0.084）以及其他基线 +0.250 至 +0.445。对比"刻意严格（intentionally stringent）"——因为 Codex 本身已是专用终端外壳（terminal harness）。
- **RQ2 — 搜索动态**：最终选中的外壳在三个基准上都优于基础配置：
  - Terminal-Bench：0.722 → 0.806
  - LiveCodeBench：0.900 → 0.967
  - FinanceAgent：0.600 → 0.767
  FinanceAgent 随轮次持续提升（第 8–9 轮附近峰值 65.0%）；LiveCodeBench 在 91.2%–95.0% 的窄区间内饱和。最终检查点有时低于训练中峰值，因为选择是基于验证集的。
- **RQ3 — 跨数据集迁移**：在 Terminal-Bench 上学到的外壳使 MMMLU +0.030、StrongReject +0.030、SWE-Bench Pro +0.059；LiveCodeBench 外壳帮助 MMMLU 与 StrongReject；FinanceAgent 外壳帮助 StrongReject 与 LawBench。已饱和的套件（HumanEvalFix、Reasoning-Gym-Easy）无变化。迁移"正向但有选择性（positive but selective）"。
- **RQ4 — 跨基础模型迁移**（Terminal-Bench，外壳在 GPT-5.3-Codex 上训练，不重训）：每个模型都得到提升，平均增益 **+0.098**，范围 +0.038（GPT-4.1）至 +0.233（GLM-5）。

  | 模型 | 基础得分（Base） | MemoHarness |
  |------|------|------|
  | GPT-5.3-Codex | 0.722 | 0.806 |
  | Claude-Sonnet-4.6 | 0.530 | 0.583 |
  | Gemini-3.1-Pro | 0.611 | 0.694 |
  | Qwen3.5-397B-A17B | 0.444 | 0.528 |
  | GLM-5 | 0.500 | 0.733 |
  | GPT-4.1 | 0.500 | 0.538 |
  | DeepSeek-V3.2 | 0.333 | 0.444 |

- **RQ5 — 成本**（Terminal-Bench 18 任务划分，GPT-5.3-Codex）：MemoHarness 使用 14.18M 输入 token，其中 **13.32M 已被缓存（cached）**，总成本 $6.89——低于 Codex（$10.28）与 Claude Code（$9.51），高于 Terminus（$6.68）与 OpenCode（$2.34），后两者"精度大幅更低（substantially lower accuracy）"。

## 结论与局限

**结论**：MemoHarness"把过去的执行转化为可供未来案例复用的经验（turns past executions into reusable experience for future cases）"，使外壳搜索同时具备诊断性与复用性；改进控制层是"对模型缩放（model scaling）与手工外壳工程（manual harness engineering）的实用补充（a practical complement）"。未来工作包括：完全无监督的搜索、更大规模的验证、组件归因（component attribution）、在线经验累积（online experience accumulation）。

**局限（附录 A）**：
- 主要 Terminal-Bench 评估使用 18 个任务的留出划分与点估计，"并非完整的统计刻画（not a full statistical characterization）"。
- 并非所有基线都是采用相同模型/运行时的纯脚手架移植（pure scaffold transplant）。
- 未对经验库、全局模式与测试时适配做完整组件消融（component ablation）。
- 成本分析依赖观测到的可缓存性；缓存复用率较低的部署可能会得到不同的成本。
- 控制器与诊断算子使用"实用启发式（practical heuristics）"——可复现但未必最优；未来应研究学习式控制器（learned controller）。

## 与 harness × 模型训练的关系

MemoHarness 把"学习"的对象从模型权重与提示词转移到 harness 本身：它在六维控制面上对 harness 做参数化，把每次自身执行的轨迹与运行时诊断写入双层经验库，由提炼器从失败簇中抽取跨案例的全局规律，从而把逐案例经验上升为可复用的全局知识，并在测试时按案例检索这些经验、为每个用例实例化一个专属 harness——整个过程不需要任何模型权重更新、测试时标签或反馈。这意味着 harness 的"学习"发生在两个阶段：训练期通过"正确性优先的字典序选择"选出全局最优外壳 W⋆，测试期通过检索适配产出案例专属外壳 W(x)。它与模型训练（权重微调、蒸馏、缩放）是正交且互补的两条路径：模型缩放决定基础能力上限，而 harness 学习则从执行经验中挤出更充分的端到端收益——并且学到的 harness 还能跨基础模型迁移（平均 +0.098，最高 +0.233）。因此二者可以叠加而非互斥：模型侧负责"能力"，harness 侧负责"把能力用好"，MemoHarness 证明后者本身也可以从经验中持续学习。
