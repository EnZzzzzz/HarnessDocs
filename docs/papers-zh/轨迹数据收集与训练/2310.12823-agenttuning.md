# AgentTuning：为大型语言模型赋予通用智能体能力（AgentTuning: Enabling Generalized Agent Abilities for LLMs）

- 作者 / 机构：Aohan Zeng（曾奥涵）‡§、Mingdao Liu（刘明道）‡、Rui Lu（陆睿）‡、Bowen Wang（王博文）‡、Xiao Liu（刘潇）‡§、Yuxiao Dong（董宇骁）‡、Jie Tang（唐杰）‡；‡清华大学（Tsinghua University），§智谱AI（Zhipu.AI）
- 出处：arXiv:2310.12823（后发表于 ACL 2024 Findings）
- 原文链接：https://arxiv.org/abs/2310.12823

## 摘要（中文翻译）

开源大型语言模型（LLM）在各种任务上的出色表现极大地推动了 LLM 的发展。然而，当它们作为智能体（agent）去处理现实世界中的复杂任务时，其表现远远逊色于 ChatGPT 和 GPT-4 等商业模型。这类智能体任务将 LLM 作为负责规划（planning）、记忆（memorization）和工具调用（tool utilization）的中央控制器，需要精细的提示（prompting）方法与稳健的 LLM 相结合，才能取得令人满意的性能。虽然已有许多针对特定智能体任务的提示方法被提出，但缺乏聚焦于在**不损害 LLM 通用能力**的前提下，从根本上提升 LLM 自身智能体能力的研究。在这项工作中，我们提出了 AgentTuning，一种简单而通用、能够在保持 LLM 通用能力的同时增强其智能体能力的方法。我们构建了 AgentInstruct，一个包含高质量交互轨迹（interaction trajectories）的轻量级指令微调数据集。我们采用混合指令微调（hybrid instruction-tuning）策略，将 AgentInstruct 与来自通用领域的开源指令结合使用。我们使用 AgentTuning 对 Llama 2 系列进行指令微调，得到 AgentLM 模型。评估表明，AgentTuning 能够在不影响通用能力的情况下赋予 LLM 智能体能力；其中 AgentLM-70B 在未见过的（unseen）智能体任务上与 GPT-3.5-turbo 相当，展现出泛化的智能体能力。我们在 https://github.com/THUDM/AgentTuning 开源了 AgentInstruct 数据集以及 AgentLM-7B、13B、70B 模型，为智能体任务提供开放、强大的商业 LLM 替代方案。

## 核心贡献

- **首个多智能体任务的交互轨迹指令微调尝试**：AgentTuning 是第一个使用跨多个智能体任务的交互轨迹对 LLM 进行指令微调（instruction-tuning）的方法，而非只针对某一特定智能体任务设计提示或框架。
- **AgentInstruct 数据集**：一个轻量级指令微调数据集，包含来自 6 个多样化真实世界任务的 **1,866 条经过验证的交互轨迹**，每一步决策都带有高质量的思维链（Chain-of-Thought, CoT）推理。构建过程完全自动化，可轻松扩展到新的智能体任务。
- **混合指令微调策略**：将 AgentInstruct 与通用领域指令按一定比例（最终选定 η=0.2）混合进行监督微调，在增强智能体能力的同时保留通用能力。
- **AgentLM 模型系列**：基于 Llama 2 chat 系列微调得到的 AgentLM-7B / 13B / 70B。AgentLM-70B 是**第一个在智能体任务上匹敌 GPT-3.5-turbo 的开源 LLM**，且不损害通用任务（MMLU、GSM8K、HumanEval、MT-Bench）的表现。
- **开源**：数据集与三个规模的模型全部开源（THUDM/AgentTuning）。

## 方法（中文翻译）

AgentTuning 的目标是：在至少维持 MMLU、GSM8K、HumanEval 等通用能力的前提下，提升 LLM 的**泛化性智能体能力**。方法分两步：先构建 AgentInstruct 数据集，再用它进行指令微调。给定一个智能体任务，其交互轨迹可记录为对话历史 (u1, a1, …, un, an)，每条轨迹有一个最终奖励 r ∈ [0,1]，反映任务完成情况。

### AgentInstruct 数据集的构建（三个阶段，全程自动化）

采用 GPT-3.5（gpt-3.5-turbo-0613）和 GPT-4（gpt-4-0613）自动完成，覆盖 6 个来自 AgentBench 的代表性任务：ALFWorld（家务）、WebShop（在线购物）、Mind2Web（网页导航）、Knowledge Graph（知识图谱）、Operating System（操作系统）与 Database（数据库）。

1. **指令构建（Instruction Construction）**：对于有训练集的任务（ALFWorld、WebShop、Mind2Web、Knowledge Graph）直接使用其训练划分。对没有训练集的 OS 与 Database 任务，采用两种方式合成指令：
   - **任务派生（Task Derivation）**：从 BIRD（仅含 SELECT 的数据库基准）派生指令——用 BIRD 的问题与参考 SQL 构造轨迹并查询数据库作为答案，再让 GPT-4 补全思维过程；或直接让 GPT-4 与数据库交互收集轨迹，与 BIRD 参考 SQL 的执行结果比对后只保留正确答案。
   - **自指令（Self-Instruct）**：让 GPT-4 生成 OS 相关任务及参考解与评测脚本，再让另一个 GPT-4 求解收集轨迹，用评测脚本比对两者答案一致者保留；DB 任务的非 SELECT 操作（INSERT/UPDATE/DELETE）也以类似方式构造。作者对测试集数据泄漏风险做了系统性分析，未发现泄漏证据。
2. **轨迹交互（Trajectory Interaction）**：以 GPT-4 作为智能体进行交互（Mind2Web 因指令量大、预算受限部分使用 gpt-3.5-turbo-0613）。采用 1-shot 评估方式提供完整交互范例。交互中模型先输出思维（thought）再执行动作（action），环境反馈后循环直至成功或达到 token 上限；连续重复输出 3 次视为重复失败；输出格式错误时用 BLEU 匹配最相近的合法动作。采用 ReAct 作为推理框架，使每条动作都带有 CoT 解释轨迹；对缺少思维的任务派生轨迹，用 GPT-4 补全思维以保持一致。
3. **轨迹过滤（Trajectory Filtering）**：依据最终奖励自动筛选高质量轨迹——除 Mind2Web 外均要求 r=1（完全正确）；因 Mind2Web 过难，采用阈值 r≥2/3 以保留足够轨迹。过滤的有效性得到验证：7B 规模下用未过滤轨迹训练在 held-in 与 held-out 任务上均显著更差（未过滤 1.34/0.47 vs 过滤后 1.96/0.65），说明**智能体任务中数据质量优于数据数量**。

AgentInstruct 最终含 1,866 条轨迹（总指令 35,341 条），各任务平均轮次 1.00–13.52，过滤率 0.52%–35.2%。

### 混合指令微调与训练设置

- **通用域指令（General Domain Instructions）**：从 ShareGPT 数据集选取英文对话，得到 GPT-3.5 对话 57,096 条、GPT-4 对话 3,670 条；因 GPT-4 回复质量更高，按 GPT-4 与 GPT-3.5 约 1:4 的比例采样。
- **混合训练（Mixture Training）**：损失函数为 J(θ) = η·E~Dagent~[log πθ(y|x)] + (1−η)·E~Dgeneral~[log πθ(y|x)]。在 7B 模型上以 0.1 为步长扫描 η∈[0,1]，最终取在 held-out 上表现最好的 η=0.2。实验发现**仅用智能体数据训练反而导致泛化性能下降**，说明通用能力对智能体能力泛化起关键作用。
- **训练设置**：以 Llama-2-{7,13,70}b-chat 为基础，按 Vicuna 方式统一为多轮对话格式，只对模型输出计算损失；用 Megatron-LM 训练；学习率 7B/13B 为 5e-5、70B 为 1e-5；batch size 64、序列长度 4096；AdamW + 余弦调度（2% warm-up）；7B/13B 用张量并行（tensor parallelism），70B 额外加流水线并行（pipeline parallelism）。

## 实验结果

评测采用 6 个 held-in（训练同源）与 6 个 held-out（未见）任务，覆盖家务、购物、网页导航、知识图谱、操作系统、数据库、科学实验、日常电脑任务、Wiki QA、网页交互、无观测推理与对抗卡牌游戏；通用能力用 MMLU（知识）、GSM8K（数学）、HumanEval（代码）、MT-Bench（人类偏好）衡量。总分按 AgentBench 方式对每个任务在模型间归一化后加权平均。

**主要结论要点：**
- AgentLM 在 held-in 与 held-out 任务上均显著超越同规模的 Llama 2，同时通用任务表现与 Llama 2 持平（最高仅 ±7% 波动，70B 为 +1%），证明增强智能体能力未损害通用能力。
- **泛化幅度随规模放大**：held-out 任务提升 7B 为 +76%、13B 为 +57%、70B 高达 +176%，归因于更大模型更强的泛化能力。AgentLM-70B 的 held-in 总分（2.55）逼近 GPT-4（2.75），held-out 总分（1.40）接近 GPT-3.5（1.49），且在若干任务上 13B/70B 甚至超过 GPT-4。
- **误差分析**（ALFWorld、WebShop、Knowledge Graph）：AgentTuning 显著减少基础性错误，如无效动作（invalid action）、短期/长期重复（repetition）与拒绝作答（refuse to answer）；说明 Llama 2 chat 本身已具备智能体潜力，AgentTuning 是"激活"而非"过拟合"了智能体能力。案例分析显示，在 ALFWorld 中 Llama-2-70b-chat 重复同一动作而失败，AgentLM-70B 会在失败后调整动作；在 Knowledge Graph 中 Llama-2 遇到函数错误时拒绝修复并转求用户实现，AgentLM-70B 则给出正确函数调用。
- **消融实验**：
  - 仅用 agent 数据训练：held-in 显著提升（如 7B 达 1.34）但 held-out 与通用任务崩溃（7B：0.09 / 0.22），证实通用指令对泛化至关重要；混合训练在 held-in 与 held-out 上均接近最优。有趣的是 7B/13B 规模下混合训练的 held-out 提升几乎与仅用通用数据相当，只有 70B 才出现大幅跃升，提示实现最优 agent 泛化可能需要特定的模型规模。
  - 单任务微调（7B）显示主要收益落在对应任务，多数任务相互促进，但 Mind2Web 因单轮格式与多轮任务差异大而跨任务增益最小。

## 结论与局限

**结论**：本文研究如何为 LLM 赋予泛化的智能体能力，弥合开源与商业 LLM 在智能体任务上的差距。AgentTuning 先构建覆盖 1,866 条已验证交互轨迹的 AgentInstruct 数据集，再设计将 AgentInstruct 与通用域指令混合的指令微调策略，并用其对 Llama 2 系列微调得到开源 AgentLM。AgentLM 在未见过的智能体任务上表现强劲，同时在 MMLU、GSM8K、HumanEval、MT-Bench 上保持通用能力。截至论文发表，**AgentLM-70B 是第一个在智能体任务上匹配 GPT-3.5-turbo 的开源 LLM**。

**局限**（论文正文未设独立"Limitations"小节，以下依据文中论述整理）：
- **对 GPT-4 轨迹质量的依赖**：即便 GPT-4 在部分真实世界智能体任务上也会失败，AgentInstruct 质量受上限约束；Mind2Web 过滤率仅 0.52%，需把阈值放宽到 r≥2/3 才能凑足样本。
- **覆盖任务数量有限**：仅 6 个任务、1,866 条轨迹；跨场景泛化（尤其在 70B 以下规模）仍然有限，小规模模型的泛化提升几乎来自通用数据。
- **规模依赖性**：held-out 泛化的显著跃升仅在 70B 出现，提示模型规模可能是瓶颈。
- **数据泄漏风险**：Self-Instruct 与任务派生合成指令存在与测试集重合的隐患，作者虽经分析未发现泄漏，但仍需警惕。
- **与顶尖商业模型的差距**：AgentLM-70B 仍明显低于 GPT-4，且预算约束导致 Mind2Web 部分交互由 GPT-3.5 完成，可能影响该任务数据质量。

## 与 harness × 模型训练的关系

AgentTuning 同时触及 agent 研究的两个正交层面，与"harness（运行框架）× 模型训练"的主题高度契合。其一，论文确认**模型本身的能力是智能体成功的关键变量**：同样的 ReAct 提示/运行框架（harness）下，基础 Llama 2 因大量"格式错误、重复生成、拒绝作答"等基础错误而近乎失效，而 AgentLM 则能在同一框架内稳定完成任务——说明 harness 只是必要条件，模型训练（对齐/指令微调）决定了智能体能力的下限。其二，AgentTuning 的方法论（用高奖励交互轨迹微调 + 与通用数据混合保持泛化、奖励过滤、CoT 推理轨迹）提供了一条**可复用的模型训练管线**：任何 harness 收集到的多轮工具调用轨迹，都可仿照 AgentInstruct 的"指令构建—轨迹交互—轨迹过滤"三阶段流程转化为微调数据，再以混合比例 η 与通用数据联合训练，从而让下游模型在既有 harness 上获得泛化智能体能力。这与 harness 侧关注"如何构建可控、可观测、可扩展的 agent 运行环境"互补：harness 决定上限的工程性，模型训练决定上限的能力性，二者共同决定 agent 系统的最终表现。
