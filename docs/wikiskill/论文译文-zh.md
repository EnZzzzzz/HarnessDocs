# WikiSkill：将 Agent 经验编译为持久知识以实现技能进化（译文）

- 原文标题：WikiSkill: Compiling Agent Experience into Persistent Knowledge for Skill Evolution
- 作者：Liyan Tang, Cyrus Rashtchian, Chun-Sung Ferng, Andrew Tomkins, Da-Cheng Juan, Tu Vu（通讯作者：lytang@google.com, ttvu@google.com）
- 机构：Google Research / Virginia Tech
- arXiv: 2608.27454（2026-08-27）

## 摘要（Abstract）

Agent 技能（agent skill）将专业知识与工作流封装为可复用的资源，用于扩展 AI agent 的能力。近期工作可以从 agent 经验中自动发现此类技能，使 agent 能够通过交互逐步适应。然而，指导技能开发的洞见通常散落在优化历史之中，限制了它们在迭代之间的系统性复用。我们提出 WikiSkill，一个将 agent 技能与持久知识库（wiki）协同进化的框架。概括而言，WikiSkill 将原始执行经验、积累的知识与可执行的技能分离开来，同时持续地把经验整合进 wiki，使后续的技能更新可以建立在 wiki 之上。在多个基准和模型上，WikiSkill 始终优于最先进的技能进化（skill-evolution）方法，并在大多数「模型—基准」设置下优于无技能基线。我们发现技能进化与模型规模扩展（model scaling）互为补充：更大的模型通常从进化技能中获益更多，而配备技能的小模型可以超过没有技能的大得多的模型。我们还发现，进化出的技能可以跨模型和跨模型家族有效迁移，且由其他模型进化出的技能有时可以超过自进化技能。最后，我们的消融实验证实，wiki 中的持久知识积累对有效的技能进化至关重要。这些结果表明，系统化地积累和提炼 agent 经验，对开发可复用、可迁移的技能大有裨益。

## 1 引言（Introduction）

通用 AI agent 正越来越能够跨领域完成复杂任务（Patwardhan et al., 2026; Jackson et al., 2025; Merrill et al., 2026; Phan et al., 2026）。然而，可靠地完成真实世界任务往往需要特定领域的专门知识（例如程序性知识和工作流）。Agent 技能（Zhang et al., 2025; Li et al., 2026; Chen et al., 2026a; Liu et al., 2026）提供了一种轻量、开放的格式，可以在不更新模型参数的情况下捕获这类专门知识。其核心在于：一个技能将指令、脚本和其他资源打包为一个可复用的、基于文件系统的模块（即一个有组织的目录）（Zhang et al., 2025; Li et al., 2026; Anthropic, 2026; Xia et al., 2026b）。这种设计使专业知识在兼容技能的各 agent 之间保持一致、可审计、可复用。它还支持渐进式披露（progressive disclosure）（Jiang et al., 2026），即 agent 在任何时刻只加载相关内容，从而节省上下文空间。更广泛地说，技能提供了一种独立于模型参数来积累知识的自然机制。

然而，开发有效的技能仍然充满挑战。大多数 agent 技能是人工编写的，这要求预先设想 agent 将需要的程序性知识和工作流（Li et al., 2026; Liang et al., 2026; Xu and Yan, 2026）。这一挑战催生了近期的一类工作：通过在训练任务上执行 agent、分析成功与失败的轨迹（trajectory），并基于所得经验来提炼技能，从而迭代式地开发 agent 技能（Yuksekgonul et al., 2025; Agrawal et al., 2026; Alzubi et al., 2026; Ni et al., 2026; Ouyang et al., 2026; Yang et al., 2026）。

一个关键的设计问题是：如何在技能进化的全过程中保存和组织 agent 学到的东西。已有工作以不同方式回答这个问题。EvoSkill（Alzubi et al., 2026）维护既往提案及其评估结果的累积历史；Trace2Skill（Ni et al., 2026）从执行轨迹中提取并整合经验教训，形成技能更新；SkillOpt（Yang et al., 2026）则利用被拒绝编辑的反馈和按轮次（epoch）的元指导。然而，这些方法都没有把所学内容维护为一种独立的、不断演化的知识表示。受 Karpathy（2026）关于 LLM Wiki 的观点启发——他主张将经验编译为持久的、可复利增长的知识——我们提出如下问题：agent 经验能否同样被编译为持久知识，以支持长期的技能进化？我们提出 WikiSkill，它在原始经验和可执行程序（即技能）之间加入了一个结构化的知识层。这一层使技能开发得以建立在跨迭代不断得到更好支撑和整合的知识之上，而不是建立在散落在技能进化产物各处的知识之上。

WikiSkill 将 agent 工作区组织为三层：存储不可变执行轨迹的原始层（Raw Layer）、维护结构化知识的 Wiki 层（Wiki Layer），以及包含不断演化的程序性知识的技能层（Skill Layer）（图 2）。每次迭代涉及四个组件：使用当前技能执行 rollout 的推理 Agent（Inference Agent）、将轨迹整合进 wiki 的 Wiki 维护者（Wiki Maintainer）、利用 wiki 和轨迹提出技能更新的技能提案者（Skill Proposer），以及保留能提升验证集性能的更新的门控与回滚（Gating and Rollback）机制。技能更新可以被回滚，但 wiki 会持久存在，使未来的更新可以建立在积累的知识之上。概括而言，这些组件构成一个持续循环：经验被整合为持久知识，进而支撑技能进化。

我们在五个基准上评估 WikiSkill，涵盖数学推理（LiveMathematicanBench（He et al., 2026））、网络搜索（SealQA（Pham et al., 2026））、电子表格操作（SpreadSheetBench（Ma et al., 2024））、长上下文文档问答（OfficeQA（Singhvi et al., 2025））以及交互式具身任务（ALFWorld（Shridhar et al., 2021）），并使用来自 Qwen（Qwen Team, 2026a; Qwen Team, 2026b）、Gemma（Gemma Team, 2026）和 Gemini（Google DeepMind, 2026）家族的五个模型。我们发现 WikiSkill 优于现有技能进化方法，并在大多数设置下优于无技能基线。有趣的是，技能进化与模型规模扩展互为补充：在 Qwen 家族内，WikiSkill 分别为 4B、9B 和 27B 模型带来 12.3%、17.5% 和 23.9% 的平均性能提升，收益随模型规模增大而增加。与此同时，进化技能可以弥补可观的模型规模差距：配备 WikiSkill 的 Qwen-3.5-9B 超过了无技能的 Qwen-3.6-27B（47.4% 对 39.4%）。我们进一步发现，进化技能可以跨模型家族有效迁移，并可超过自进化技能。例如在 ALFWorld 上，Qwen-3.5-9B 使用 Qwen-3.6-27B 进化出的技能达到 70.2%，而使用自身进化的技能为 63.4%。这些结果表明，技能发现与技能执行是两种不同的能力。最后，我们的分析表明持久 wiki 是这些收益的关键，支持了我们的假设：跨迭代积累和提炼知识可以改善技能进化。

综上，我们的主要贡献是：

- 我们提出 WikiSkill，一个将 agent 技能与持久知识库协同进化的框架，该知识库持续地组织和提炼来自 agent 经验的知识。
- 我们在五个基准和五个模型上证明，WikiSkill 始终优于现有技能进化方法，消融实验证实了持久知识积累的重要性。
- 我们系统地研究了进化技能与模型能力的相互作用，表明技能进化与模型规模扩展互为补充，且进化技能可以跨模型有效迁移，有时甚至超过自进化技能。

总而言之，我们希望我们的工作能激发更多关于 agent 如何从经验中积累、组织和复用知识的基础性研究。

## 2 问题设定（Problem Setup）

我们对 LLM agent 的迭代式技能进化任务进行形式化。令 $\mathcal{D}=\{(x_i, y_i)\}_{i=1}^{N}$ 为任务数据集，其中 $x_i$ 表示一个任务实例，$y_i$ 表示其标准答案。我们将 $\mathcal{D}$ 划分为三个互不相交的划分：训练任务 $\mathcal{D}_{\text{train}}$、验证任务 $\mathcal{D}_{\text{val}}$ 和测试任务 $\mathcal{D}_{\text{test}}$。

Agent $\pi$ 是一个基于 LLM 的系统，配备一组工具 $\mathcal{U}$（例如 bash shell、搜索 API 或文件读取器）和一个活跃技能集合 $S=\{s_1, s_2, \dots, s_M\}$。技能是一个模块化的、基于文件系统的目录，将特定领域的程序性知识打包为指令、脚本和其他资源（Zhang et al., 2025; Li et al., 2026; Chen et al., 2026a; Liu et al., 2026）。具体来说，每个技能包含一个带有 frontmatter 元数据（唯一名称和简要描述）的 SKILL.md 文件，以及完整的程序性指令和适用条件。技能集合 $S$ 初始化为空（$\emptyset$），并针对每个数据集通过进化过程开发。

在执行任务 $x_i$ 时，agent 接收任务上下文 $x_i$ 以及对可用技能 $S$ 的访问权。agent 使用其工具和技能与环境进行多步交互，生成执行轨迹 $\tau_i \sim \pi(x_i; S)$。轨迹 $\tau_i=(o_1, a_1, o_2, a_2, \dots, o_T, a_T)$ 由观测 $o_t$ 和动作 $a_t$ 组成（动作可能包括对 $\mathcal{U}$ 中工具的调用）。最后一个动作 $a_T$ 输出预测答案 $\hat{y}_i$。预测的正确性由领域特定的评分函数 $f(\hat{y}_i, y_i)\in[0,1]$ 评估。对于任意任务划分 $\mathcal{D}_{\text{split}}\subset\mathcal{D}$，在 $\mathcal{D}_{\text{split}}$ 的所有任务实例上 rollout agent $\pi(\cdot;S)$，得到相应的执行轨迹集合 $\mathcal{T}_{\text{split}}=\{\tau_i\sim\pi(x_i;S)\}_{(x_i,y_i)\in\mathcal{D}_{\text{split}}}$。任务划分上的性能 $\mathcal{R}(\mathcal{T}_{\text{split}})$ 是所有任务实例 $(x_i, y_i)\in\mathcal{D}_{\text{split}}$ 的平均得分。

在 WikiSkill 中，第 $k$ 次迭代的系统状态表示为元组 $(S_k, W_k)$，其中 $S_k=\{s_1, \dots, s_M\}$ 表示活跃程序性技能集合，$W_k$ 表示持久知识库（Wiki）。候选技能更新会受到验证门控的约束，并在得分下降时被回滚；而知识库 $W_k$ 则跨迭代持久存在并不断累积。从 $(S_0, W_0)=(\emptyset, \emptyset)$ 出发，WikiSkill 在迭代 $k\in\{1,\dots,K\}$ 中协同进化联合状态 $(S_k, W_k)$，利用训练 rollout $\mathcal{T}_{\text{train},k}$、模式整合，以及基于 $\mathcal{T}_{\text{val},k}$ 的验证门控，来最大化在未见过任务 $\mathcal{D}_{\text{test}}$ 上的最终测试性能 $\mathcal{R}(\mathcal{T}_{\text{test}})$。

## 3 方法（Methodology）

> 图 2：WikiSkill 框架概览。agent 工作区被组织为三层：不可变的执行轨迹（原始层）、跨迭代不断累积的持久知识库（Wiki 层），以及活跃程序性指令（技能层）。在每个进化循环中，推理 Agent 执行 rollout（注入活跃技能但限制 Wiki 访问），Wiki 维护者将轨迹整合进 Wiki，技能提案者（借助 ReAct 机制）提出更新，而 Wiki 在所有迭代中被保留。

我们提出 WikiSkill，一个将 agent 技能与持久知识库（wiki）协同进化的框架。WikiSkill 以三层知识架构为核心（§3.1），执行一个编排好的进化循环：agent 执行 rollout，Wiki 维护者整合轨迹并更新 wiki，技能提案者提出技能更新，门控机制对变更进行过滤（§3.2）。

### 3.1 三层知识架构（Three-Layer Knowledge Architecture）

WikiSkill 工作区由三个不同的层组成，如图 2 所示，分述如下。

**原始层（raw/）** 该层存储每次迭代中从训练样本收集的原始执行轨迹 $\tau_i\in\mathcal{T}_{\text{train},k}$。这些轨迹捕获 agent 完整的逐步交互过程，包括推理、工具调用、工具调用输出和最终答案。在我们的设定中，Wiki 维护者和技能提案者 agent 可以访问这些原始轨迹来分析 agent 行为。为保留原始历史，该层是不可变的。

**Wiki 层（wiki/）** 该层将原始轨迹编译为结构化的、可复利增长的知识，并在技能进化全过程中得到维护。它包含一个模式目录（patterns/），其中填充了独立的 markdown 文件，记录特定的失败模式或成功策略，以及可操作的规避方法。关键的是，该层通过进化日志（logs.md，由 Wiki 维护者更新）和技能影响追踪器（skill-impact.md，在验证门控之后由外层循环 harness 以程序化方式更新），提供跨优化迭代的长期历史感知。这些记录使 Wiki 维护者和技能提案者能够：（1）观察完整的技能采纳历史，从而不再重复提出被拒绝的干预；（2）追踪先前迭代中提出过什么以及这些提案是否成功；（3）识别哪些错误跨迭代反复出现。wiki 在迭代之间不会被重置，而是在整个进化过程中持续积累和编译知识。

**技能层（skills/）** 该层包含进化出的活跃技能集合 $S$，其中编码了推理 Agent 可以读取的程序性知识。WikiSkill 中的每个技能目录包含两个文件：SKILL.md，包含技能的完整内容；PURPOSE.md，将技能映射回启发其创建或修改的 Wiki 模式。图 3 展示了技能层与 Wiki 层交互的详细示例，并在第 5.3 节的案例研究中加以解释。

### 3.2 进化 Agent 与 Wiki 编排（Evolutionary Agents and Wiki Orchestration）

WikiSkill 循环由四个组件构成。在每次迭代中，推理 Agent（§3.2.1）使用 skills/ 中的活跃技能执行任务，在 raw/ 中产生不可变的执行轨迹。在训练 rollout 期间，推理 Agent 被限制访问 Wiki 层，因为我们的消融研究（§5.1）表明，训练期间允许 wiki 访问会对技能开发产生负面影响。接下来，Wiki 维护者（§3.2.2）将这些原始轨迹与现有 wiki/ 层结合起来分析，以诊断失败并提取成功策略，更新持久的模式目录和进化日志。随后，技能提案者（§3.2.3）审阅更新后的 wiki，并读取最新迭代的执行轨迹，以在 skills/ 中生成或修改候选技能。最后，门控与回滚机制（§3.2.4）在验证集上评估候选技能，接受成功的修改，或在变更降低性能时回滚技能集合。完整的进化算法见附录 A 中的算法 1。

#### 3.2.1 推理 Agent 的技能供给（Skill Provisioning for the Inference Agent）

在第 $k$ 次迭代，推理 Agent $\pi$ 以活跃技能集合 $S_{k-1}$ 为条件，使用环境工具 $\mathcal{U}$ 执行多轮轨迹：

$$\tau_i\sim\pi(x_i;S_{k-1}) \tag{1}$$

在 WikiSkill 中，活跃技能 $S_{k-1}$ 的完整内容被直接注入推理 Agent 的系统提示词。沿用先前工作（Yang et al., 2026; Ni et al., 2026），这种全量注入设定确保程序性指令在任务执行期间立即可用，从而消除了技能触发或检索失败这一混杂变量。

#### 3.2.2 Wiki 维护者：模式整合（Wiki Maintainer: Pattern Consolidation）

在第 $k$ 次迭代，在训练集 $\mathcal{D}_{\text{train}}$ 上获得 rollout 轨迹 $\mathcal{T}_{\text{train},k}$ 之后，我们对成功与失败的执行轨迹采样子集 $\mathcal{T}_{\text{sample},k}\subset\mathcal{T}_{\text{train},k}$（采样预算与分层标准见附录 C），以避免上下文窗口限制。Wiki 维护者 agent $\mathcal{M}_{\text{WM}}$ 将这些观测整合进持久 wiki $W_{k-1}$，产生中间 wiki 状态 $W^{\prime}_{k}$：

$$W^{\prime}_{k}\leftarrow\mathcal{M}_{\text{WM}}(W_{k-1},\mathcal{T}_{\text{sample},k}) \tag{2}$$

Wiki 维护者 agent 接收完整的 wiki 上下文 $W_{k-1}$ 以及采样轨迹 $\mathcal{T}_{\text{sample},k}$。它对失败任务进行根因分析，并从通过的任务中提取成功策略。在每次迭代中，Wiki 维护者可以在 wiki/patterns/ 下创建新的模式页面，也可以用新的证据或改进后的解决方案更新已有的模式页面。模式页面的更新以增量式的、基于补丁（patch）的编辑方式应用（例如追加、替换或插入文本片段）。每当模式被修改时，Wiki 维护者会修订 index.md 目录以反映当前状态，并将本次迭代发现的摘要追加到进化日志 logs.md。每次迭代创建或更新的模式数量没有硬性上限；Wiki 维护者根据轨迹和当前 wiki 状态自行决定哪些更新是必要的。

#### 3.2.3 Wiki 引导的技能提案者（Wiki-Informed Skill Proposer）

提案者 $\mathcal{M}_{\text{P}}$ 是一个基于 LLM 的 agent，负责技能的发现与提炼。在第 $k$ 次迭代，提案者以多轮 ReAct 风格（Yao et al., 2023）运作。为避免在分析冗长的执行历史时耗尽上下文窗口，提案者不会被给定一组固定的预采样轨迹；相反，它最初获得的是 wiki 索引 $I(W^{\prime}_{k})$、历史技能影响追踪器（skill-impact.md），以及所有训练任务结果的简要摘要（通过/失败状态、预测答案和标准答案）。作为自主 agent，它主动推理并使用环境工具（read_file）按需选择和检查特定的模式页面与原始执行轨迹 $\tau_i\in\mathcal{T}_{\text{train},k}$，在综合出提案 $P_k$ 之前诊断根因：

$$P_{k}\leftarrow\mathcal{M}_{\text{P}}(W^{\prime}_{k},S_{k-1},\mathcal{T}_{\text{train},k}) \tag{3}$$

在每次迭代中，技能提案者产生一个原子化的提案 $P_k$，针对单个技能：要么创建一个新技能，要么对目标现有技能应用一次增量式的、基于补丁的编辑。

#### 3.2.4 门控与回滚（Gating and Rollback）

提案 $P_k$ 生成后，被应用到工作区，产生候选技能集合 $S^{\prime}_{k}=\text{Apply}(S_{k-1},P_k)$。系统在验证集 $\mathcal{D}_{\text{val}}$ 上评估 $S^{\prime}_{k}$，得到验证轨迹 $\mathcal{T}_{\text{val},k}$ 和得分 $\mathcal{R}(\mathcal{T}_{\text{val},k})$。采纳决策由下式决定：

$$S_{k}\leftarrow\begin{cases}S^{\prime}_{k}&\text{若 } \mathcal{R}(\mathcal{T}_{\text{val},k})>\mathcal{R}_{\text{best}}\\ S_{k-1}&\text{否则}\end{cases} \tag{4}$$

若被采纳，候选技能被保留为新的活跃技能集合 $S_k$，基准性能阈值 $\mathcal{R}_{\text{best}}$ 被更新为 $\mathcal{R}(\mathcal{T}_{\text{val},k})$。在进化循环开始之前，$\mathcal{R}_{\text{best}}$ 被初始化为基线验证得分 $\mathcal{R}(\mathcal{T}_{\text{val},0})$，即在 $\mathcal{D}_{\text{val}}$ 上评估空技能集合 $S_0$ 得到的分数。若在进化过程中的任何时刻验证得分达到最大值（$\mathcal{R}_{\text{best}}=1.0$），进化循环提前终止。若被拒绝，系统丢弃候选技能修改，并将技能集合恢复到最近一次成功的配置 $S_{k-1}$。值得注意的是，无论采纳决策如何，wiki $W_k$ 从不被回滚；积累的模式和日志跨所有迭代持久存在，以确保长期知识保留。每次验证评估之后，外层循环编排 harness 以程序化方式向 wiki/skill-impact.md 追加一条记录，即 $W_{k}\leftarrow\text{Update}(W^{\prime}_{k},P_k,\mathcal{R}(\mathcal{T}_{\text{val},k}),a_k)$，记录提案元数据、目标技能名称、修改的统一 diff、验证得分 $\mathcal{R}(\mathcal{T}_{\text{val},k})$ 以及最终采纳结果 $a_k\in\{\text{Accepted},\text{Rejected}\}$。这完成了第 $k$ 次迭代的 wiki 状态转移 $W_{k-1}\to W_k$，为过去的干预提供客观的、可作为依据的审计轨迹，供技能提案者在后续迭代中查阅，以避免重复失败的修改。

## 4 实验与结果（Experiments and Results）

### 4.1 实验设置（Experimental Setup）

**数据集** 我们在五个跨领域的基准上进行评估：数学推理（LiveMathematicianBench（LiveMath）（He et al., 2026））、网络搜索（SealQA（Pham et al., 2026））、电子表格操作（SpreadsheetBench（SpreadSheet）（Ma et al., 2024））、长上下文文档问答（OfficeQA（Singhvi et al., 2025））以及交互式具身任务（ALFWorld（Shridhar et al., 2021））。数据集细节和统计信息见附录 B。

**基线** 我们将 WikiSkill 与三个代表性的技能进化基线进行比较：Trace2Skill（Ni et al., 2026）、EvoSkill（Alzubi et al., 2026）和 SkillOpt（Yang et al., 2026）。它们都共享相同的总体循环：rollout agent、分析执行轨迹、提出技能修改，并通过验证对变更进行门控。我们还评估每个模型在无技能条件下作为无技能基线的表现。这些框架的详细描述以及优化器 API 调用复杂度分析见附录 D。我们将比较聚焦于专门的技能进化框架，而非通用自动提示词优化器（如 GEPA（Agrawal et al., 2026）），因为先前工作表明专门的技能进化流水线始终优于通用提示词优化方法（Yang et al., 2026）。

**模型** 我们同时使用闭源模型和开源权重模型来评估 WikiSkill 和各基线。闭源模型方面，我们使用 Gemini-3.5-Flash（Google DeepMind, 2026）。开源权重模型方面，我们评估 Qwen-3.5-4B/9B-Instruct（Qwen Team, 2026a）、Qwen-3.6-27B（Qwen Team, 2026b）和 Gemma-4-31B-It（Gemma Team, 2026），并使用 vLLM 框架（Kwon et al., 2023）进行部署。

#### 4.2.1 跨模型与跨任务的技能进化（Skill Evolution Across Models and Tasks）

**WikiSkill 在模型和数据集上带来一致的提升。** 如表 1 所示，WikiSkill 在所有五个模型上都取得了最高的平均性能。与每个模型上最强的竞争技能进化方法相比，WikiSkill 在 Qwen-3.5-4B、Qwen-3.5-9B、Qwen-3.6-27B、Gemma-4-31B 和 Gemini-3.5-Flash 上的平均性能分别提升了 3.3、5.1、10.0、5.8 和 12.0 个百分点。这些提升在各设置下是一致的：WikiSkill 在大多数「模型—数据集」组合上优于无技能基线，并在所有模型上、在 5 个数据集的平均性能上追平或超过最强竞争方法。这些提升跨越了多样的领域，且幅度可以相当可观。例如，WikiSkill 将 Gemini-3.5-Flash 在 LiveMath 上从 33.0% 提升到 72.6%，在 SpreadSheet 上从 50.5% 提升到 76.6%，并将 Qwen-3.6-27B 在 ALFWorld 上从 52.8% 提升到 77.6%。相比之下，现有技能进化方法的一致性较差。例如，EvoSkill 在 LiveMath 上大幅提升了 Qwen-9B（28.2% → 58.1%），但在同一基准上降低了 Gemma-4-31B 的表现（33.9% → 29.8%），而 SkillOpt 在 SealQA 上降低了 Gemini-3.5-Flash 的表现（29.4% → 28.2%）。这些结果表明，WikiSkill 在各设置下带来的提升既更强也更可靠。

**技能进化的收益随模型能力增长，并与模型规模扩展互补。** 在 Qwen 家族内，WikiSkill 带来的平均提升随模型规模增长：Qwen-3.5-4B 为 +12.3 个百分点，Qwen-3.5-9B 为 +17.5，Qwen-3.6-27B 为 +23.9。这一趋势在 SpreadSheet 上尤为明显，WikiSkill 分别为三个模型带来 +6.5、+9.3 和 +40.9 个百分点的提升，表明技能进化的收益可以随模型规模大幅增长。与此同时，进化技能可以弥补可观的模型规模差距：配备 WikiSkill 的 Qwen-3.5-9B 达到 47.4% 的平均准确率，超过无技能 Qwen-3.6-27B 的 39.4%，而配备 WikiSkill 的 Qwen-3.5-4B 达到 38.5%。我们的结果表明，模型能力与进化出的程序性知识提供了互补的性能来源：更强的模型可以通过开发和执行更有效的技能从技能进化中获得更大价值，而有效的技能可以让较小的模型超过不使用技能的、大得多的模型。

**技能进化的收益在不同数据集之间也差异显著。** 我们的结果表明，某些数据集比其他数据集更适合技能进化。对于 Qwen-3.6-27B，WikiSkill 在 OfficeQA 上提升 11.6 个百分点、在 SealQA 上提升 14.1 个百分点，而在 ALFWorld、LiveMath 和 SpreadSheet 上分别提升 24.8、28.0 和 40.9 个百分点。类似的差异也出现在其他模型上。LiveMath 持续从技能进化中受益，所有五个模型的收益在 20.6 到 39.6 个百分点之间；而 ALFWorld 在 WikiSkill 为其进化技能的四个模型上的收益为 14.0 到 29.3 个百分点（Gemini-3.5-Flash 因提前停止而被排除）。相比之下，OfficeQA 因其长上下文文档检索的要求而带来独特挑战。较大的模型能有效利用进化出的搜索工作流来浏览冗长的文档（例如 Qwen-3.6-27B 提升 +11.6 个百分点，Gemini-3.5-Flash 提升 +12.1 个百分点），而 Qwen-3.5-4B 难以在长上下文中执行这些多步搜索工作流，退回其默认的阅读行为，导致轻微的性能下降。

#### 4.2.2 WikiSkill 的跨模型技能迁移（Cross-Model Skill Transfer with WikiSkill）

**进化技能可以跨模型有效迁移，且迁移技能可以超过自进化技能。** 表 2 评估了 WikiSkill 使用不同源模型开发的技能在跨推理模型时的迁移效果。迁移技能频繁地同时超过无技能基线和自进化技能。例如，Qwen-3.6-27B 的技能将 Qwen-3.5-9B 在 SpreadSheet 上提升至 50.5%，而无技能时为 24.3%、自进化技能时为 33.6%；并将 Gemma-4-31B 在 LiveMath 上提升至 73.7%，而无技能时为 33.9%、自进化时为 56.7%。值得注意的是，有效的迁移也会从小模型到大模型发生：Qwen-3.5-4B 的技能将 Gemma-4-31B 在 LiveMath 上提升至 73.1%、在 ALFWorld 上提升至 66.9%。我们的结果表明，更强的源模型并不一定能产生更好的技能，一个模型从经验中开发的程序性知识可以跨模型规模和模型家族迁移。

**进化技能的可迁移性取决于其捕获的是通用程序还是模型特定的变通方法。** 表 2 的结果表明，WikiSkill 既能产生可跨模型迁移的通用程序性知识，也可能产生导致负迁移的模型特定策略。LiveMath 的技能跨模型迁移得尤其好：Qwen-3.5-4B 和 Qwen-3.6-27B 的技能分别将 Gemini-3.5-Flash 从 33.0% 提升至 67.5% 和 73.9%。相比之下，SpreadSheet 表现出强烈的「源—目标」相互作用：Qwen-3.5-4B 的技能将 Gemini-3.5-Flash 的表现从 50.5% 拉低至 18.1%，而 Qwen-3.6-27B 的技能则将其提升至 63.4%。我们的误差分析识别出这一负迁移背后的两个因素。第一，Qwen-3.5-4B 的技能编码了低层级的变通方法，例如单行 Python 命令和字符串转换规则，这些帮助较小的模型避免执行失败，却限制了 Gemini-3.5-Flash 等更强模型使用完整的端到端脚本。第二，碎片化的诊断流程引入了冗余的工具调用，可能在任务完成前耗尽 Gemini-3.5-Flash 的交互预算。

**迁移技能的效用还取决于推理模型执行它们的能力。** 我们现在来看不同的推理模型如何使用同一源模型开发的技能。在 Qwen 家族内，更强的模型能从相同的程序性知识中获得更大价值。例如，Qwen-3.6-27B 的 SpreadSheet 技能分别将 Qwen-3.5-4B、Qwen-3.5-9B 和 Qwen-3.6-27B 相对各自无技能基线提升了 18.4%、26.2% 和 40.9%。OfficeQA 提供了一个「模型开发出的技能对别的模型比对自己更有用」的案例：Qwen-3.5-4B 的技能将其自身表现从 30.2% 降至 28.5%，却将 Qwen-3.6-27B 从 42.1% 提升至 52.9%。我们的轨迹分析表明，在长上下文场景中，较小的模型可能被冗长的文档上下文分散注意力，无法遵循详细的多步搜索指令，转而退回其默认的文档阅读行为；而更强的模型能更可靠地在长上下文中执行技能所规定的结构化导航流程。综合来看，这些结果区分了自我进化通常会混同的两种能力：从经验中发现有用的程序性知识，以及在推理时有效执行这些知识。

## 5 分析与讨论（Analysis and Discussion）

**持久 wiki 知识大幅改善技能进化。** 如表 3 所示，当推理 Agent 的 wiki 访问被禁用时，让技能提案者访问持久 wiki 可将平均基准性能从 48.7% 提升至 63.7%（+15.0%），其中 LiveMath（51.3% → 72.6%）和 SpreadsheetBench（49.9% → 76.6%）的提升尤为可观。没有跨迭代积累的持久知识，技能提案者难以解决复杂的失败模式。

**进化期间推理 Agent 的 wiki 访问会降低最终技能质量。** 当技能提案者可以访问持久 wiki 时，在训练 rollout 期间再给推理 Agent 提供 wiki 访问，会将平均基准性能从 63.7% 降至 60.9%，其中 LiveMath 从 72.6% 大幅降至 64.8%。我们假设，当推理 Agent 在训练 rollout 期间同时可以访问技能和 wiki 时，一些任务求解知识可能直接从 wiki 而非技能中获得，这会使所得轨迹对技能开发的信息量降低。

### 5.2 定性分析：技能与 Wiki 动态（Qualitative Analysis: Skill and Wiki Dynamics）

为更好地理解 WikiSkill 如何跨模型和数据集进化知识与技能，我们分析了进化过程中积累的 wiki 模式和产出的技能（表 4），以及成功的技能更新在各迭代中被采纳的时间分布（附录表 5）。

**WikiSkill 持续积累 wiki 模式，同时产出简洁的技能。** 表 4 汇总了跨模型和基准的技能与 wiki 模式的创建和编辑情况及其平均长度。跨模型来看，Qwen 模型产生更长的程序性技能（118.9–128.6 行），而 Gemma-4-31B 和 Gemini-3.5-Flash 产生更紧凑的技能（分别为 45.1 和 81.2 行）。Wiki 模式的积累也因模型而异，平均创建 6.3–8.9 个模式、编辑 7.0–18.4 次。跨基准来看，SpreadSheet 产生最长的技能（142.5 行）和最多的 wiki 模式（9.8 个），而 LiveMath 产生最短的技能（84.6 行）和最少的 wiki 模式（4.4 个）。总体而言，这些结果表明技能结构和 wiki 积累都会随模型和数据集而变化。

**技能提炼贯穿整个进化过程。** 附录表 5 将被采纳的技能更新按早期（迭代 0–1）、中期（迭代 2–4）和后期（迭代 5–7）阶段分组。跨模型来看，初始阶段占被采纳更新的 39%–52%，中期和后期仍有相当比例。跨基准也呈现类似模式，39%–58% 的被采纳更新发生在初始阶段。持续的提炼在 SealQA 上尤为明显，33% 的被采纳更新发生在中期阶段，28% 发生在后期阶段。结合第 5.1 节的消融实验，这些结果表明持久知识积累支撑了跨迭代的持续技能提炼。Wiki 层保存了反复出现的错误、被拒绝的提案和进化历史，为技能提案者的后续更新提供积累的上下文。下面我们通过一个案例研究来说明这些积累的知识如何指导技能进化。

## 6 相关工作（Related Work）

**经验驱动的 Agent 技能进化。** Agent 技能编码可复用的程序性知识，使 LLM agent 能够利用过去的经验应对未来的任务（Zhang et al., 2025; Li et al., 2026; Anthropic, 2026; Xia et al., 2026b; Zhou et al., 2026; Wang et al., 2026; Xu and Yan, 2026）。近期的框架使 agent 能够通过从过去的执行轨迹中发现和提炼程序性知识来自我改进（Yuksekgonul et al., 2025; Agrawal et al., 2026; Ouyang et al., 2026; Xia et al., 2026a; Lu et al., 2026）。EvoSkill（Alzubi et al., 2026）、Trace2Skill（Ni et al., 2026）和 SkillOpt（Yang et al., 2026）等方法使用专门的 agent 流水线来分析任务 rollout 并更新模块化的技能文档（Zhang et al., 2026b）。然而，这些方法都没有把所学内容维护为一种独立的、不断演化的知识表示。WikiSkill 引入了一个持久 Wiki 层，将经验跨迭代整合为结构化知识，使后续的技能更新能够系统地建立在积累的知识之上。

**技能增强的 Agent 与 Agent 自我改进。** 除了构建高质量的技能，技能增强的 agent 还必须在执行过程中有效地选择和利用相关技能（Chen et al., 2026a; Liu et al., 2026）。随着可复用技能数量的增长，近期工作探索了技能检索（skill retrieval），即从技能库中为每个任务选择相关技能（Zheng et al., 2026; Su et al., 2026; Cho et al., 2026; Shi et al., 2026; Ye et al., 2026）。WikiSkill 则专注于技能质量本身，与技能检索相互独立。另一条工作线优化更广义的 agent harness，包括提示词、上下文、工具、记忆和工作流（Lou et al., 2026; Lee et al., 2026; Zhang et al., 2026a; Chen et al., 2026b; Lin et al., 2026）。这些方法通过分析执行轨迹和环境反馈来搜索更好的 agent 配置，从而改进 agent 系统。这一方向与 WikiSkill 互补：WikiSkill 专注于在保持整体 agent harness 固定的情况下，进化可复用的程序性技能。

## 7 结论（Conclusion）

我们提出了 WikiSkill，一个将 agent 技能与持久的、可复利增长的知识库（wiki）协同进化的框架。通过将 agent 工作区组织为三个不同的层，WikiSkill 使技能开发得以建立在跨迭代不断得到更好支撑和整合的知识之上。一个编排好的循环将经验整合进 wiki，从积累的知识中提出技能改进，并基于验证性能对变更进行门控。在实证上，WikiSkill 在五个基准和五个推理模型上始终优于现有技能进化方法，并在大多数「模型—数据集」组合上优于无技能基线。除这些总体收益外，技能进化与模型规模扩展互为补充：更大的模型通常从进化技能中获益更多，而配备技能的小模型可以超过没有技能的、大得多的模型。与此同时，进化技能可以跨模型和跨模型家族有效迁移，并可超过自进化技能。最后，我们的消融实验证实，持久知识积累对有效的技能进化至关重要。

### 局限性（Limitations）

WikiSkill 存在若干局限性，为未来工作指明了方向。第一，为隔离技能质量并避免技能检索带来的混杂效应，我们的研究沿用先前工作，将活跃技能直接注入 agent 提示词。这一设定没有评估技能检索或触发，而随着可用技能数量的增长，这一点会变得重要。第二，我们的验证门控要求每个被采纳的提案都必须提升验证得分，这排除了那些保持当前性能不变、但可能在后续迭代中带来收益的中性提案。为确保公平比较，我们遵循先前的技能进化框架（Yang et al., 2026; Alzubi et al., 2026）采用这一严格标准。探索更灵活的采纳标准是未来工作的重要方向。第三，Wiki 层跨迭代持续积累模式页面、进化日志和提案 diff，但 WikiSkill 目前缺乏自动修剪 wiki 的机制。随着知识在更长的进化运行中不断积累，这种修剪可能变得必要。最后，虽然我们的基准套件包含长上下文文档推理（OfficeQA）和多步工具交互，但并未覆盖跨越数百个环境动作或数小时的超长程任务。开发在线技能自适应方法，在单次长程执行 rollout 内提炼程序性知识，仍是未来工作的重要方向。
